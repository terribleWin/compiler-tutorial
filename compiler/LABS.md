# 从空文件到完整编译器：8 个可验收实验

这些实验以 `src/sprout.cpp` 为最终参考实现。先在自己的草稿文件中完成当前阶段，再与同名类对照。每个实验都有输入、观察点和验收标准；实验简化不改变最终语言规范。完整测试可先只挑选相关用例，不要求第一天就通过全套。

## 实验 1：让字符流变成 Token 流

**先实现：** `Pos`、`Token`、`Lexer::peek/take/scan`，再写一个只扫描并打印 Token 的 `main`。测试源字符串必须由一个具名 `std::string` 保存，不能把 `Lexer` 持有的引用指向临时字符串。

```text
fn main() -> int { let letter = 12; print(letter >= 10); return 0; }
```

逐项检查：`letter` 是一个 id，不应被拆成关键字 `let` 和剩余字符；`>=` 是一个 Token；`->` 是一个 Token；最后存在 EOF。把字符串后面加 `// 中文注释`，结果除 EOF 列位置外应不变。加单个 `&` 应报未知字符。

**验收：** 每个 Token 都有从 1 开始的行列号；输入末尾恰好停在数字或标识符后也不越界。当前完整实现可用 `sprout --tokens file.spr` 作为结果对照。

**自测题：** 若先判断关键字 `let` 再继续读标识符，`letter` 会怎样？为什么关键字识别应放在完整拼写读完以后？

## 实验 2：构建表达式树，先不执行

**先实现：** `Expr` 与 `Parser::primary/expression`。最小阶段只支持整数、括号、四则运算。下面的结构是抽象树示意，不是 Token 顺序：

```text
1 + 2 * 3       20 - 5 - 2
    +               -
   / \             / \
  1   *           -   2
     / \         / \
    2   3       20  5
```

`expression(min)` 先读左侧，再决定当前运算符能否绑定。右侧调用 `expression(当前优先级 + 1)`，使同级运算符留给外层循环，从而左结合。可将 `+1` 暂时删去，比较 `20-5-2` 的树形，观察它变成 `20-(5-2)`。

**验收：** `1+2*3` 的根是 `+`，其右子节点为 `*`；`(1+2)*3` 的根是 `*`。缺右括号时，错误位置指向实际遇到的 Token。网站示意与完整 `--ast` 输出相比会省略语句节点和类型标记。

## 实验 3：从语法树走到“有意义的程序”

**先实现：** 块、变量声明、赋值、符号表；随后加类型检查。符号表不要只用一个全局 map，应使用 `vector<map<string, Symbol>>` 表示作用域栈。

```text
fn main() -> int {
    let x = 10;
    {
        let x = x + 1;
        print(x);
    }
    print(x);
    return 0;
}
```

分析内层声明时，先检查初始化表达式，再插入新符号。因此其右侧读取外层 `x`。最后两个声明应有不同槽号。将内层 `let` 改为 `x = x + 1;`，此时不创建新槽位，而是写外层槽。

**验收：** `let x=x;` 在没有外层 x 时拒绝；同块 `let x=1; let x=2;` 拒绝；`let x=1; x=true;` 拒绝。`if(1)` 拒绝，因为 int 不能隐式转 bool。完整实现用 `--check` 验收这些静态错误。

## 实验 4：用栈机器完成第一个编译闭环

**先实现：** `Instruction`、`Generator` 的 PUSH/算术/PRINT/RET 和 VM。不要直接遍历 AST 求值；先生成指令，再让 VM 只读指令。

对以下完整程序：

```text
fn main() -> int { print(1 + 2 * 3); return 0; }
```

忽略源位置，字节码应为：

```text
0 PUSH 1
1 PUSH 2
2 PUSH 3
3 *
4 +
5 PRINT_INT
6 PUSH 0
7 RET
```

**手工跟踪：** 栈从 `[]` 到 `[1]`、`[1,2]`、`[1,2,3]`、`[1,6]`、`[7]`、`[]`。实现二元算术时先弹右值，再弹左值；用 `8-3` 验证顺序，不能只用加法测试。

**验收：** `sprout file.spr` 输出 7。`sprout --bytecode file.spr` 只展示指令，不执行，也不打印 7。每条指令保留对应源位置，运行时除零能回到原来的运算符。

## 实验 5：分支、循环与跳转回填

**先实现：** LOAD/STORE/JZ/JMP。JZ 消耗栈顶条件，条件为 false 才跳转。第一次生成 JZ 时目标还未知，先写 0 占位，再在分支体生成完成后回填。

```text
fn main() -> int {
    let i = 0;
    while (i < 3) {
        print(i);
        i = i + 1;
    }
    return 0;
}
```

**验收：** 输出 0、1、2，各占一行；将条件改为 `i < 0` 时无输出。循环每次回到条件计算开始，不能跳回 JZ 本身，也不能重复执行 `let i=0`。查看 `--bytecode`，指出前向退出边与后向循环边。

**短路扩展：** `false && (1/0 == 1)` 输出 false，不触发除零；`true || (1/0 == 1)` 输出 true。这里不能先生成左右两侧，再做普通 AND/OR。对比 `Generator::expr` 对 `&&`、`||` 的两个布局，并画出到达右侧表达式的条件。

## 实验 6：函数帧与递归

**先实现：** 先建函数签名表，再分析函数体；调用时建立新的局部变量数组和操作数栈。参数槽从 0 开始。调用者从左到右压参数，CALL 按相反顺序弹出并恢复形参顺序。

```text
fn subtract(a: int, b: int) -> int { return a - b; }
fn main() -> int {
    print(subtract(8, 3));
    return 0;
}
```

**验收：** 结果为 5，不能是 -5。随后运行 `examples/fibonacci.spr`，第十个输出为 34。递归各层的 n 必须独立；把局部变量数组错误地共享后，可观察递归结果如何受破坏。

**静态检查：** 参数数目、类型、返回类型必须在执行前验证。`if/else` 两侧都 return 可证明返回；只有单侧 return 还不够。返回检查是保守分析，不能把“这次测试碰巧会返回”当作所有输入都返回的证明。

## 实验 7：让错误可以复现、可以定位

**先实现：** `Error`、检查算术、执行预算。错误不是 0 或其他普通值，不能继续参与计算。

分别写出并执行：

```text
fn main()->int { print(2147483647 + 1); return 0; }
fn main()->int { print(7 / 0); return 0; }
fn main()->int { while(true){} return 0; }
```

上面三行是三个独立文件，不能放在同一程序中，因为会重复定义 main。预期分别报溢出、除零、超过执行步数。第三个示例不会永远挂住。

**验收：** `--check` 对这些示例均通过，因为没有静态类型问题；实际执行才失败。对 `let n=1; n=true;`，`--check` 必须失败且不能先执行 print。运行全部测试，核对静态错误和运行错误边界。

**边界题：** 为什么 int32 乘法需要先转 int64 再相乘？为什么只在赋值到 int64 时转型来不及？`int64_t result = int32_a * int32_b;` 的乘法究竟以什么类型完成？

## 实验 8：另一种后端与差分测试

**先实现：** 将经过 Checker 标注的 AST 转换成独立 C++11 源码。用临时变量保存各子表达式，确保从左到右求值。生成目标代码不意味着调用 `system()` 执行用户字符串；本实现只输出文本，由用户明确运行工具链。

先运行 `--emit-cpp`，再用 g++ 编译生成文件。用 `examples/short-circuit.spr` 比较 VM 与本机程序，输出都应为：

```text
false
true
3
true
4
true
```

**验收：** 使用 `python tests/run_tests.py ./sprout --native g++`，成功路径、溢出与除零等异常路径都应一致。测试包含有副作用的实参，能发现错误依赖 C++11 实参求值顺序的问题。资源预算采用不同粒度，接近上限的程序不作逐步等价比较。
