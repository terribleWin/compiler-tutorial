# 学习路线：让每一步都有产物

不要用“读完多少页”判断掌握程度。更可靠的标准是：你能否解释一个输入为何得到这个输出，能否添加一个测试证明自己的修改。以下时间仅供安排，遇到不熟悉的 C++ 或数据结构时可以多停留。

## 路线一：第一次接触编译原理

| 阶段 | 阅读 | 动手产物 | 验收 |
| --- | --- | --- | --- |
| 准备，约 1–2 周 | 第 1–3 章 | 构建 Sprout，跑通示例，学会读错误 | 独立修改程序并重新运行 |
| 定义规则，约 1 周 | 第 4–6 章 | 写出语言规范、Token 表、一个 NFA 到 DFA 的推导 | 解释 `>=` 为什么不能切成两个 Token |
| 构造前端，约 2–3 周 | 第 7–10 章 | 解析表达式、作用域与类型检查 | 对错误程序给出位置与原因 |
| 完成闭环，约 2 周 | 第 11–12 章 | AST → 字节码 → VM，运行递归 | `fib(10)` 输出 55；短路避免除零 |
| 解释中间层，约 2–3 周 | 第 13–16 章 | 画 CFG、手算数据流和 SSA，添加一个优化 | 优化前后程序结果一致 |
| 走向本机，约 2–3 周 | 第 17–19 章 | 构建生成的 C++，解释 ABI，试写 LLVM IR | 说明每一层由谁完成 |
| 完成工程，持续练习 | 第 20–22 章 | 添加一项语言特性和完整回归测试 | 提交规范、实现、测试与限制说明 |

若你还不会编程，请先完成第 2 章的容器、函数、对象和所有权小练习。编译器是很好的练习项目，但同时学习语法、内存和编译理论会增加认知负担。每次只引入一个新的困难。

## 路线二：已经会 C++，想快速建立全景

先读第 1、4 章，运行配套代码；按 `--tokens`、`--ast`、`--check`、`--bytecode`、默认执行的顺序观察同一个输入。阅读第 5、7、10、11、12 章完成主线，然后补第 6、8 章的形式理论。不要用“看过一个输出”代替自己实现；最少选一个阶段重新写一次。

## 第一次的 90 分钟实验

1. 下载[配套源码](source.html)，确认终端中 `g++ --version` 能输出版本。
2. 构建编译器并运行 `compiler/examples/hello.spr`。
3. 把输出表达式改成 `2 + 3 * 4`，先预测，再运行。
4. 打开[交互实验室](lab.html)，比较 `2 + 3 * 4` 和 `(2 + 3) * 4` 的树与指令。
5. 故意漏写分号、引用不存在的名字、令整数除以零。分别记录错误发生在哪个阶段。
6. 为刚才发现的一个边界条件写下“输入、预期、实际、结论”。

这次实验的目标是建立地图。自动机、LR、SSA 都会在后面推导，不要求在第一次运行之前掌握。

## 如何真正从零实现

配套的 `compiler/` 是可运行参考答案。只复制完整文件能得到可执行程序，却不能替代构造过程。建议另建 `my-sprout/`，按以下顺序写代码，每一步都保留测试：

1. 接收一个整数并输出；不要先设计所有类。
2. 扫描整数、符号与位置，打印 Token；此时还没有 Parser。
3. 支持括号与四则运算，先生成 AST，再输出树。
4. 把 AST 编译成 `PUSH/ADD/MUL`，写一个十几行的栈机。
5. 添加局部变量、符号表、类型检查，先拒绝非法程序。
6. 添加 `if` 和 `while`，学会跳转回填与栈高度核对。
7. 添加函数签名、参数、本地槽位、调用帧、返回值，最后加入递归。
8. 把每一步的错误样例变成回归测试，再尝试优化和第二后端。

每个阶段的实作可以对照相应章的教学片段，但片段不承诺可直接替换参考实现的某一段。参考实现的对象布局和全部边界规则以 [源码导读](source.html)与 `compiler/SPEC.md` 为准。

## 主线实现与扩展实验的边界

| 能力 | 随书编译器 | 学习目标 |
| --- | --- | --- |
| Lexer、Parser、AST、静态语义 | 已实现 | 第 4–10 章 |
| 栈式字节码、跳转、调用帧、递归 | 已实现 | 第 11–12 章 |
| 生成独立 C++11 源码 | 已实现 | 第 17、20 章 |
| 直接发射汇编或目标文件 | 扩展实验 | 第 17–19 章 |
| 三地址 IR、SSA、优化 pass | 扩展实验 | 第 13–16 章 |

C++ 目标路径也是编译：Sprout 源语言被翻译为另一种语言，宿主 C++ 编译器再完成优化、机器码生成和链接。本书没有把宿主后端所做的工作算作 Sprout 已实现的机器后端。

## 结业项目怎么选

第一次推荐添加 `for` 循环，并把它降低为已有的 `while`，这样可以完整经历规范、词法、语法、作用域、控制流、测试六个环节。第二次再选择数组或 LLVM 后端，避免同时更改语言、内存模型和目标平台。

交付物应包含：新语法的 EBNF；至少三个成功示例；至少五个拒绝/运行错误示例；对求值顺序、类型与作用域的说明；测试运行命令；已知限制。能解释“为什么这个错误必须被拒绝”，比实现一长串未定义行为更有价值。

## 遇到困难时怎样回退

- Parser 出错：先看 Token，不要立即怀疑文法算法。
- 语义检查出错：用最小作用域例子，先移除循环与函数。
- VM 输出不对：观察字节码和每一步栈变化，核对跳转目的地。
- 递归出错：只调用一次恒等函数，再增加第二层调用。
- 优化出错：保存未优化输出，缩小到一个基本块，检查溢出与副作用。

每章读完勾选“已完成”，并保留自己的实验记录。本站的进度保存在浏览器本地；更换设备不会同步。
