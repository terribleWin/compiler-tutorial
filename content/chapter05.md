# 第05章 扫描器：让字符成为有位置的 Token

## 本章目标与前置

前置是第02章的字符串遍历与第04章的词法规则。本章要实现的不是“看见数字就算出答案”，而是稳定地识别输入中的最小语法单位，并为每个单位保留来源。完成后，你应该能手工列出一个程序的 Token，解释最长匹配与关键字识别，并知道如何报告非法字符和文件结尾。

## 5.1 Token 是一次信息整理

源字符串 `let total = 12 + 3;` 可以整理成以下序列。这里的名称是教学表示，不要求与工具的具体枚举名逐字一致。

| 种类 | 原始文字 | 起始位置（行:列） |
| --- | --- | --- |
| Let | `let` | 1:1 |
| Identifier | `total` | 1:5 |
| Assign | `=` | 1:11 |
| Integer | `12` | 1:13 |
| Plus | `+` | 1:16 |
| Integer | `3` | 1:18 |
| Semicolon | `;` | 1:19 |
| End | 空 | 1:20 |

Token 同时保留种类与原始文字。解析器通过种类判断结构，通过文字获取变量名或诊断内容。空格没有成为 Token，但依然影响列号。文件结束使用独立的 End Token，使解析器能够统一处理“没读到需要的符号”和“已经读完”。

## 5.2 只让一个函数推进游标

扫描器通常维护源字符串、当前位置、行号和列号。读取但不消费叫 `peek`；读取并向前推进叫 `advance`。把更新位置的责任集中起来，避免某个分支忘记换行后重置列号。

```cpp
// 教学片段：游标骨架，需配合包含头文件和类成员使用。
char peek() const {
    return current == source.size() ? '\0' : source[current];
}

char advance() {
    if (current == source.size()) {
        throw std::runtime_error("unexpected end of input");
    }
    char c = source[current++];
    if (c == '\n') {
        ++line;
        column = 1;
    } else {
        ++column;
    }
    return c;
}
```

真实实现要把“到达源字符串末尾”与“字符串中恰好出现零字节”区分开，不能完全依赖 `\0` 哨兵代表所有情况。本课程示例中的简化 `peek` 只帮助说明控制流程；所有读取之前依然要有边界判断。

源码位置可以同时保存字节偏移和行列号。偏移适合提取源片段，行列适合显示给人。要说明列号以字节、Unicode 码点还是显示宽度计数。ASCII 语言核心可以先采用字节计数；制表符和中文注释的视觉宽度仍需在诊断界面中单独考虑。

## 5.3 一个分支识别一种类别

扫描循环的顺序可以写成以下伪代码：

```text
while 尚未到达末尾:
    保存本 Token 的起点
    if 当前字符是空白: 消费空白并继续
    if 当前与下一字符组成 //: 跳到行尾并继续
    if 当前字符能开始标识符: 扫描完整名字，再查关键字表
    else if 当前字符是数字: 扫描完整十进制数字
    else if 能组成双字符运算符: 消费两个字符并产生 Token
    else if 是已知单字符符号: 消费一个字符并产生 Token
    else: 报告非法字符及其起点
追加唯一的 End Token
```

名字必须先扫描完整再判断关键字。输入 `while_count` 不能拆成 `while` 和 `_count`，因为整段都满足标识符规则。`let` 才会在关键字表中命中，`letter` 则保持普通标识符。

数字扫描也不能只读一个字符。对 `123`，游标从第一个数字开始，持续前进到第一个非数字，原文范围才算确定。数值转换失败应给出“整数超出允许范围”，不要让 `stoi` 抛出的宿主异常信息直接冒充面向用户的语言诊断。

## 5.4 最长匹配与规则优先级

输入 `a <= b` 时，如果看见 `<` 就立刻提交，剩下的 `=` 会改变整个程序。最长匹配要求在同一起点选择可以匹配的最长 Token，因此双字符运算符应在对应单字符之前尝试。常见例子包括 `==`、`!=`、`<=`、`>=`、`&&`、`||` 和函数返回箭头 `->`。

最长匹配不表示把一行尽可能吞成一个 Token，而是必须先满足某条 Token 规则。例如 `a+b` 不能合成一个标识符，因为 `+` 不属于标识符字符集。同样，`===` 可以按规则分为 `==` 与 `=`，然后交给后面的语法阶段判断这串 Token 是否构成合法程序。

规则匹配长度相同时，还需要优先级。例如生成器中关键字规则与标识符规则都能匹配 `if`，工具通常按规则顺序或显式规则决定种类。手写扫描器使用“完整名字后查表”，把这件事写得更直接。

## 5.5 整数转换的安全做法

扫描数字时可以逐位累积，但必须在乘10和加数字之前判断边界。对于最大允许正值 `limit` 和当前数字 `digit`，若 `value > (limit - digit) / 10`，则下一步会越界。这里所有量都应在足够宽的无符号或有符号表示中，并保证减法本身合法。

不要先在32位变量里做 `value = value * 10 + digit`，再问它有没有超过最大值；错误已经在运算中发生。也不要因为源文件来自自己就省略检查。编译器的任务本来就是接收尚未证明正确的输入。

一元负号由语法层处理，所以最小负整数的表示需要扫描器与语法层协商。可以允许更宽的无符号字面量临时表示，再在一元负号和类型检查中处理；也可以限制正字面量范围并提供明确的构造方式。重点是规则应统一，而不是偶然依赖转换函数。

## 5.6 亲手调试扫描过程

将以下程序保存为 `tokens.spr`：

```sprout
fn main() -> int {
    // 名字中的关键字不应被拆开
    let while_count = 12;
    print(while_count <= 20 && true);
    return 0;
}
```

运行 `./sprout --tokens tokens.spr`。验收时检查：注释没有进入普通 Token 流；`while_count` 只有一个标识符 Token；`12` 是一个整数；`<=` 与 `&&` 各只有一个 Token；`return` 的行号仍然正确。

然后依次测试三个边界：文件完全为空；文件以注释结束且没有最后换行；文件在单独一个 `&` 后结束。前两个应能正常完成词法分析，虽然空文件后续可能违反入口要求；第三个应报告不完整或非法的逻辑运算符。把“词法可以完成”与“整个程序合法”分开判断。

## 5.7 常见错误与复杂度

最常见的故障是游标不前进，导致扫描器在一个非法字符上无限循环。每条成功路径都必须消费至少一个字符；失败路径应该停止并返回错误。读取双字符符号时不要在末尾直接访问 `current + 1`，要通过安全的查看函数处理。

对于这门手写扫描器，每个字符至多经过有限次检查，扫描时间应与输入长度近似成正比。一般自动生成词法器的最长匹配实现若大量回溯，可能出现额外代价；因此不能把“所有词法器都天然线性”当作无条件定理。第06章会建立自动机视角，让你理解为什么扫描器可以用状态转换表示。

<details>
<summary>查看答案</summary>

当前位置可以匹配更长的 `!=`，应优先产生不等比较 Token。否则 Token 流变成 `x ! = y`，后面的解析器无法恢复原本的比较含义。
