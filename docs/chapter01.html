第01章 从一行代码看见整个编译器 ​

本章目标与起点 ​

本章不要求你知道自动机、汇编或语法树。你要先完成一个可以观察的实验：把自己写下的程序交给工具，看到确定的结果，再说清楚结果是怎么来的。你只需要会新建文本文件、保存文件，并愿意按照下一章补齐 C++ 基础。暂时看不懂命令中的参数没有关系，第03章会逐项解释。

这套课程把“编译原理零基础”和“编程零基础”分开处理。编译原理的概念全部从头建立；从未写过程序的读者，应先完成第02章的小练习，再回来继续。学习进度以能解释、能修改和能排错为准，不以看完多少页为准。

1.1 我们究竟要做什么 ​

假设你发明了一门叫 Sprout 的语言。你希望别人能写 print(1 + 2 * 3);，而计算机最后输出 7。计算机处理器并不认识 print，也不知道你给乘号规定了什么优先级。你需要一个工具，把这些约定转换成更低层、能够执行的表示。

这个转换工具就是本课程的编译器。它先读取完整程序，检查程序是否符合规则，再生成一串字节码指令。虚拟机执行这些指令。我们还提供另一条出口：把同一个已检查的程序生成 C++11 源码，再交给已有 C++ 编译器生成本机可执行程序。借助已有后端是合理的工程分工；后续章节会继续解释直接生成汇编所需的知识。

请始终区分三种语言：

名称本课程中的选择它的任务
源语言Sprout用户用它描述要计算的事情
实现语言C++11我们用它编写编译器本身
目标表示字节码，或生成的 C++11保存翻译结果，交给下一层执行

“用 C++ 写编译器”并不意味着编译器只能编译 C++。像用中文写一本英语语法书一样，实现语言和被解释的语言是两个不同角色。

1.2 第一份完整的 Sprout 程序 ​

在项目的 compiler 目录中，新建 hello.spr。注意文件应保存为普通文本，而不是 Word 文档；扩展名不要变成 hello.spr.txt。

sprout
fn main() -> int {
    print(1 + 2 * 3);
    return 0;
}
1
2
3
4

fn 开始定义函数；main 是整个程序的入口；圆括号中的空白表示没有参数；-> int 说明函数会返回整数。花括号围起来的是函数体。print 输出一个值，return 0 结束入口函数。分号标记一条简单语句结束。现在不需要背下所有名词，你只要把这五行当作一个完整例子。

按照第03章构建出 sprout 后，执行下面的命令。Windows 的 PowerShell 可以把工具名写成 ./sprout.exe。

text
./sprout hello.spr
1

Windows 可以把命令中的 ./sprout 替换为 ./sprout.exe。预期标准输出只有一行：

text
7
1

终端中的 7 与 return 0 是两件事。前者是程序打印给人看的内容，后者是 Sprout 的 main 计算出的返回值。参考工具正常执行结束时统一返回进程状态0，不把 Sprout 的返回值直接映射成进程状态；失败则给出非零状态。检查工具是否成功还需要查看进程退出状态，不能只看有没有文字。

1.3 沿着流水线逐层观察 ​

同一个文件可以在不同阶段停下来。下面的命令都是课程配套参考实现支持的观察入口：

text
./sprout --tokens hello.spr
./sprout --ast hello.spr
./sprout --check hello.spr
./sprout --bytecode hello.spr
1
2
3
4

具体排版以你实际构建的版本为准。你需要寻找的是结构，而不是机械比较空格：

  1. 词法分析把字符分成 fn、名字、括号、数字、运算符等 Token。print 后面的 1 与 2 不再是散落的字符。
  2. 语法分析把 Token 组织成树。加法节点的右孩子是乘法节点，因此先计算 2 * 3。
  3. 语义分析确认 main 存在、返回类型正确、运算的两端都是整数，并拒绝未声明的名字。
  4. 代码生成把树翻译成低层指令。概念上会先压入 1、2、3，做乘法，再做加法，最后打印。
  5. 虚拟机读取指令，维护运行时数据，真正完成输出。

前端负责理解源语言，后端负责构造目标表示，中间表示负责把两端连接起来。一个阶段的结果应该能作为下一个阶段的输入，而不是让每一层都重新猜测原始文字的意思。

1.4 把错误当作观察窗口 ​

将 print(1 + 2 * 3); 改为以下不同版本，每次只改一个地方。

改动你希望在哪一层发现它理由
print(1 @ 2);词法分析@ 不属于这门语言的有效符号
print(1 + );语法分析加号右侧缺少表达式
print(missing);名字解析这个位置没有可见的变量声明
print(true + 2);类型检查布尔值不支持整数加法
print(1 / 0);执行阶段这个运算违反运行时整数规则

运行时错误不等于编译器故障。例如除数来自用户计算时，编译阶段通常不能知道它最终是否为零。另一方面，编译器崩溃、无限递归或读取越界都不是合格的报错方式。本课程会建立源码位置和错误分类，帮助使用者定位自己的问题，也帮助实现者定位工具的问题。

1.5 一条可以走完的学习路线 ​

第一次学习建议分三轮。第一轮完成第01—05章，能构建工具并看懂 Token；第二轮完成语法树、作用域、类型和字节码，形成最小闭环；第三轮再做优化、SSA、汇编、链接、运行时和测试专题。后面的理论不是为了给工具堆术语，而是回答“为什么这段程序应该这样翻译”“怎样知道改写没有改变结果”。

每做完一个功能，都保存一个正常例子和一个错误例子。加入乘法时保存优先级案例；加入变量时保存未声明案例；加入函数时保存递归和参数数量案例。这样逐步增加语言能力的做法，受到 Ghuloum 增量式编译器教学论文的启发。我们的语法、实现语言和目标表示与该论文不同，采用的是逐步扩大可验证子集的教学方法。

不要把“覆盖编译器的主要领域”理解为“第一版就实现工业编译器的所有特性”。本课程可运行主线覆盖词法、语法、静态语义、控制流、函数和两种执行路径；进阶章节明确区分已实现的功能与供你继续建设的内容。数组、对象、模块、垃圾回收等功能需要额外语义和运行时支持，不能靠在目录里加一个标题就宣称完成。

1.6 练习与自查 ​

练习一：把第一份程序改为输出 9，但保留数字 1、2、3 和加号、乘号。

查看答案

使用 print((1 + 2) * 3);。括号改变树形结构：乘法节点的左孩子变成加法节点。这不是“让打印函数先执行括号”，而是在语法分析时确定表达式的分组。

练习二：有人说“有虚拟机，所以它不是编译器”。这句话遗漏了哪一步？

查看答案

遗漏了从源程序生成字节码的编译过程。是否存在编译取决于有没有翻译到目标表示；最终由处理器直接执行，还是由虚拟机执行，是另一个维度。一个系统可以同时包含编译器和解释执行字节码的虚拟机。

练习三：记录一个 Token 错误、一个语法错误和一个类型错误。不要只抄报错信息，还写下“为什么这一层拥有判断它所需的信息”。

本章验收：你能让示例输出 7，能说明三种语言的分工，并能沿着五个阶段追踪这一行表达式。接下来阅读第02章，为亲自实现这些阶段准备 C++ 基础。
