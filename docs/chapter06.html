第06章 从正则表达式走到最小 DFA ​

本章目标与前置 ​

前置是第05章的 Token 与扫描游标。本章暂停增加语言特性，用一个可以完整手算的例子理解 RE、NFA、DFA 与最小化。完成后，你应该能回答：为什么正则适合描述 Token？为什么 NFA 可以出现多个候选状态？如何把它机械地转换成每步只有一个状态的 DFA？哪些状态可以安全合并？

本章是理论实验，不要求用自动机替换已经工作的手写扫描器。你可以先完成手算，再把状态表写成代码，最后比较两种扫描方式。构造过程使用的状态编号为本课程原创。

6.1 正则表达式描述一类字符串 ​

这里的“正则”使用形式语言中的基本运算：连接、选择与 Kleene 星号。a(b|c)* 表示先出现一个 a，后面出现零个或多个 b 或 c。因此 a、ab、acbc 属于它，空串、b、aa 不属于它。

| 是选择，* 是重复零次或多次，括号用于分组。空串记作 ε，它的长度为0；空语言表示没有任何字符串，两者不能混淆。比如 r* 总包含空串，因为重复零次是一种合法选择。

正则适合描述整数和标识符等局部模式，但无法一般性地计数任意深度的配对括号。((((x)))) 需要记住未关闭括号的数量，有限个状态不够；这正是后续引入上下文无关文法和栈的原因。某些实用“正则表达式”工具有反向引用等超出形式正则的扩展，不能把其全部能力都归给有限自动机。

6.2 NFA 允许保留多个可能 ​

有限自动机有有限状态集合、输入字符集合、初态、接受态和转移关系。NFA 中，同一状态读同一个字符可以有多条转移，还可以有不消费字符的 ε 转移。接受一个字符串的条件是：至少存在一条完整路径，读完全部输入后到达接受态。

Thompson 构造按正则语法递归拼接小机器。一个字符对应一条边；连接通过 ε 接上前后机器；选择增加分叉；星号增加“零次绕过”和“再来一次”的 ε 边。你不需要猜整张图，只要保证每个局部组合都保持语言含义。

为 a(b|c)* 构造如下 NFA，初态为0，唯一接受态为8。表中未列出的边不存在。

源状态边标签目标状态
0a1
1ε2
2ε3、8
3ε4、6
4b5
6c7
5ε3、8
7ε3、8

读完 a 后，机器可以通过 ε 到达8，因此接受单独的 a。若接着读 b，走4到5，再通过 ε 回到选择入口3，或者到8停下。初态0没有 ε 路径到接受态，所以空串被拒绝。这三项检查能迅速发现星号构造中常见的接线错误。

6.3 ε-closure 是不读字也能走到的集合 ​

ε-closure(S) 表示从集合 S 中任意状态出发，只沿 ε 边能到达的全部状态，包括 S 本身。例如本例：

text
ε-closure({0}) = {0}
ε-closure({1}) = {1,2,3,4,6,8}
ε-closure({5}) = {3,4,5,6,8}
ε-closure({7}) = {3,4,6,7,8}

计算时使用工作表：先把起点加入结果，再逐个展开尚未处理的 ε 邻居，只有新出现的状态才加入工作表。ε 图可能有环，若没有“已经访问”的标记，就会无限展开。集合去重不是性能小优化，而是算法正确停止的条件之一。

move(S, c) 则只走一次标签为 c 的边，不自动展开 ε。两者合起来才是 NFA 消费一个字符后的全部可能：ε-closure(move(S, c))。

6.4 子集构造：把一组可能当成一个状态 ​

DFA 的每个状态可以表示 NFA 的一个状态集合。开始状态是 NFA 初态的 ε 闭包。对每个尚未处理的集合和每个字符，计算新的集合，给它一个编号。相同集合无论怎样到达，都必须复用同一个 DFA 状态。

只要集合中含有 NFA 接受态8，这个 DFA 状态就是接受态。现在手算输入 acbc：S → A → C → B → C，最后接受；输入 aba：S → A → B → D，最后拒绝。

从 n 个 NFA 状态理论上可以产生最多 2^n 个子集，但实际只构造从初态可达的子集。这个最坏情况提醒我们：自动机转换虽然机械可靠，空间代价并非总是很小。不要把“每步确定”误解成“状态数量一定更少”。

6.5 最小化：未来无法区分才可以合并 ​

两个 DFA 状态可以合并，当且仅当从它们出发，对所有未来输入串，接受与拒绝的结果都相同。仅仅“现在都接受”还不够，因为再读一个字符后可能分道扬镳。

初始划分按接受性得到 {A,B,C} 与 {S,D}。检查后一组：输入 a 时，S 进入接受组，D 留在拒绝组，因此必须拆开。再检查 {A,B,C}：每个状态在 a 上都进入D，在 b 或 c 上都进入这个接受组，无法进一步区分。最终三个等价类为 {S}、{A,B,C}、{D}。

最小机器就很直观：起点等一个 a；读到后停在接受状态，并在 b/c 上循环；任何不允许的字符进入死亡状态。这与正则表达式的意思完全一致。

这是易理解的划分细化思路，不是对 Hopcroft 算法全部数据结构的实现。常见表填充算法可在状态对上标记“已经可区分”，Berkeley 材料给出了这种方法和正确性证明。Hopcroft 算法进一步使用精心组织的分割工作表，在常见复杂度表达下达到 O(|Σ| n log n)；初学时先证明自己写的版本合并正确，再优化复杂度。

6.6 从语言识别器回到词法器 ​

词法器同时识别多种 Token，可以新建一个总入口，用 ε 边连到每一种规则的 NFA 初态。每个接受态除了“接受”还记录 Token 种类与规则优先级。子集里若出现多个接受态，应按规则优先级选择；扫描输入时记录最近一次接受的位置，在当前路径无法继续时回到这个位置，输出最长匹配 Token。

这个“最近一次接受”很关键。当前状态暂时不接受，并不意味着之前没有合法 Token；反过来，曾经接受也不意味着应该立即提交。比如读到 < 时可以接受单字符运算符，但接着的 = 可能形成更长的 <=。

对词法器做最小化时，初始分组必须区分不同 Token 输出，不能只分“接受/不接受”。如果把 Identifier 接受态和 Integer 接受态合并，机器虽然还可能识别相同的总语言，却丢失了应向解析器报告的类别。编译器工程中需要保留的观察结果，比单纯语言接受性更丰富。

6.7 把状态表写成一个小实验 ​

不依赖任何库，你就能把本章最小 DFA 写成教学函数：

cpp
// 完整函数教学片段：仅识别 a(b|c)*，不承担整个 Sprout 扫描。
bool accepts(const std::string& text) {
    enum State { Start, Accept, Dead };
    State state = Start;
    for (char c : text) {
        if (state == Start) {
            state = c == 'a' ? Accept : Dead;
        } else if (state == Accept) {
            state = (c == 'b' || c == 'c') ? Accept : Dead;
        }
    }
    return state == Accept;
}

6.8 练习与验收 ​

练习一：A 与 B 为什么在子集构造中是两个状态，却能在最小化中合并？

查看答案

子集构造依据集合是否完全相同，A 含1、2而 B 含5，集合不同。最小化依据所有未来串的可观察接受行为，A 与 B 对未来 a/b/c 的行为相同，所以能合并。这是两个不同的等价关系。

练习二：为 S 与 D 找一个最短区分串。

查看答案

a。从S出发接受，从D出发拒绝。空串不能区分，因为S与D本身都不接受。

练习三：将正则改成 ab*，列出最小 DFA 状态并为每一对状态找区分理由。

查看答案

仍是起点、接受状态、死亡状态三个状态，但接受状态只在b上循环，a与其他字符进入死亡状态。起点与死亡状态用a区分；接受态与另两态用空串区分。
