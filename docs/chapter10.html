CHAPTER 10 / 前端

第10章 名字解析、类型检查与返回路径#

本章目标与前置#

前置是能生成带位置的 AST。我们现在面对一棵结构正确、但未必有意义的树。本章要确定每个名字指向哪一项声明、每个表达式有什么类型、每次调用是否匹配、每条可能结束的路径是否给出返回值。完成后，你应能手算作用域查找，写出类型检查的基本递归规则，并理解保守静态分析的意义。

10.1 语法正确只是入场券#

print(unknown); 可以被完整解析；1 + true 也能形成二元节点。语法只判断结构，名字解析与类型检查负责排除这些没有按语言规则定义的含义。整个前端在代码生成前完成检查，避免虚拟机运行到一半才发现明显的静态错误。

静态语义的输入是 AST 与环境，输出可以是已绑定符号、已标注类型的 AST，或单独的分析表。阶段边界上要有明确约定：后端能否假设所有变量已绑定？能否假设条件都是布尔？若能，就由前端统一保证，后端不必处处重复猜测。

10.2 环境是一组嵌套的名字映射#

最简单的作用域实现是一个映射栈。进入块压入空映射，离开块弹出。声明插入当前最内层映射；查找从内层向外层进行，找到即停止。符号信息至少包括名字、类型、声明位置和局部编号。

// 教学片段：展示作用域结构，不是完整可替换实现。struct Symbol {    Type type;    std::size_t localId;    SourceRange declaration;};std::vector<std::map<std::string, Symbol> > scopes;const Symbol* lookup(const std::string& name) const {    for (std::size_t depth = scopes.size(); depth > 0; --depth) {        const auto& scope = scopes[depth - 1];        auto found = scope.find(name);        if (found != scope.end()) {            return &found->second;        }    }    return nullptr;}

返回的指针只适合在映射和元素寿命稳定的期间借用。若后续需要长期保存绑定，优先复制符号 ID 与类型等必要信息。不要在退出作用域后继续使用已销毁映射中的元素指针。

10.3 遮蔽不等于修改外层变量#

fn main() -> int {    let x = 10;    {        let x = x + 1;        print(x);    }    print(x);    return 0;}

参考实现规定：先检查并计算初始化表达式，再引入新变量。因此内层 let x = x + 1 中右边的 x 绑定到外层变量，得到11；之后内层名字 x 遮蔽外层名字。程序依次输出11和10。

这是一项语言设计选择，不是所有语言都相同的普遍规则。没有外层 x 时，let x = x + 1 仍然是未声明名字错误。同一个作用域再次声明同名变量被拒绝；嵌套块允许遮蔽。参数和函数最外层函数体共享一层作用域，因此不能用同层 let 重复声明参数名。

赋值与声明不同。x = x + 1; 查找已有符号并更新它，不创建新绑定。如果内层没有声明 x，它会更新可见的外层 x。静态绑定一旦确定，后端应使用对应局部编号，而不是在执行时重新遍历名字字符串。

10.4 先收集函数签名，再检查函数体#

为支持前向调用和互相递归，可以分两遍：第一遍为所有函数建立名称、参数类型序列和返回类型；第二遍分别检查函数体。第一遍拒绝重复函数名，检查入口 main 无参数并返回 int；第二遍把参数加入各自函数的局部环境。

fn isEven(n: int) -> bool {    if (n == 0) { return true; }    return isOdd(n - 1);}fn isOdd(n: int) -> bool {    if (n == 0) { return false; }    return isEven(n - 1);}fn main() -> int {    print(isEven(6));    return 0;}

编译器检查 isEven 的函数体时，需要知道 isOdd 的签名，但不必先执行或完整编译 isOdd 的函数体。这把“声明信息可用”与“函数实现已经处理完”分开了。例子只对非负参数有预期的终止行为，静态类型检查并不自动证明递归会结束。

10.5 类型规则是可以逐项执行的判断#

用 Γ 表示当前类型环境，Γ ⊢ e : T 表示“在环境 Γ 中，表达式 e 的类型是 T”。这不是新语言语法，而是我们描述检查规则的数学记号。

整数常量：                  Γ ⊢ 12 : int布尔常量：                  Γ ⊢ true : bool名字：若 Γ(x)=T，           Γ ⊢ x : T加法：若 e1:int 且 e2:int，  Γ ⊢ e1+e2 : int比较：若 e1:int 且 e2:int，  Γ ⊢ e1<e2 : bool逻辑：若 e1:bool且e2:bool，  Γ ⊢ e1&&e2 : bool

每条规则都可以变成一个 switch 分支。检查二元节点时，先递归得到左右类型，再检查运算符允许的组合，最后返回结果类型。1 < 2 < 3 的树先得到 1 < 2 : bool，再尝试把 bool 与 int 做小于比较，因此被拒绝。

等于与不等于可以比较同类型的两个 int 或两个 bool；逻辑非要求 bool，一元负号要求 int。Sprout 没有隐式 int/bool 转换。严格区分这两种类型，会让错误在更靠近来源的位置被发现。

10.6 语句的检查职责#

声明先检查初始化表达式，用其类型建立新符号；赋值先查目标符号，再要求右侧类型一致；print 检查操作数是支持打印的类型；if 和 while 要求 bool 条件；return 要求表达式类型与当前函数返回类型一致。表达式语句允许计算并丢弃结果，但仍然必须通过类型检查。

调用节点先查函数签名，再比较实参数量，最后依次比较类型。参数错误应该指向具体的那个实参，而不是只在函数结尾说“调用失败”。没有函数重载，所以不需要做多候选签名选择；以后增加重载时，名字查找与类型匹配会变成更复杂的联合过程。

短路影响执行，但不取消静态检查。false && unknown 的右边虽然不会运行，编译器仍应发现未声明名字。false && (1 / 0 == 0) 的右边名字与类型都正确，运行时则应被短路跳过，不能提前抛出除零。这一区别将在优化章节再次出现。

10.7 返回路径不是“搜到 return 就算通过”#

下面的函数存在 return，但当 n 不大于0时会直接走到函数末尾：

fn bad(n: int) -> int {    if (n > 0) {        return n;    }}fn main() -> int {    return bad(0);}

需要沿控制结构分析哪些路径会落到后面。教学上可以给每条语句计算一个属性 mustReturn，含义是“如果控制进入这条语句，它所有能够继续的路径都在内部返回，不会从正常出口离开”。

return e:                  mustReturn = true普通声明/赋值/print:       mustReturn = falseif (c) A else B:           mustReturn = A.mustReturn && B.mustReturnif (c) A:                  mustReturn = falsewhile (c) A:               保守地取 false顺序块 s1...sn:            某个必返回语句使其后正常路径不可达

对循环保守取 false，意味着即使 while(true) 肉眼看起来不退出，分析器也可以要求循环后补一个 return。这是设计得简单而可靠的保守检查。它可能拒绝某些实际上不会落出函数的程序，但不会因为随意猜测循环会执行，就接受明显缺返回的程序。完整实现细节以参考工程的返回流检查为准。

发现必返回语句后，后面的语句不可达。编译器可以告警、拒绝或继续静态检查，但要规定清楚；无论采用哪种诊断策略，都不能把不可达代码的存在误当作函数仍然需要额外返回。

10.8 属性文法如何连接这些代码#

在树上，类型往往由孩子传给父亲，是综合属性；当前作用域、预期返回类型从上下文传给孩子，是继承信息。比如加法的类型由左右子树类型决定，而 return 的合法性需要知道它所在函数的返回类型。

属性文法把这种信息流形式化：给文法符号附加属性，给产生式附加求值规则和约束。不能只看文法结构就决定所有属性都能自底向上计算；继承依赖、兄弟依赖与循环依赖会影响求值顺序。对 Sprout，手写多遍 AST 遍历比直接实现通用属性求值器更容易入门，但背后的信息流可以用同一套概念解释。

如果属性互相依赖形成循环，是否存在可计算的不动点、如何判断循环性，就进入了资料库中循环属性文法论文讨论的领域。先把本章的符号环境和类型规则写对，再研究通用求值机制，学习负担会更可控。

10.9 绑定后的树如何帮助后端#

解析时变量节点保存字符串名字；解析名字后可以附加 localId，调用节点附加函数 ID，表达式附加类型。后端不再需要做“这个x到底指谁”的查找，只需生成 LOAD 或 STORE 指向对应槽位。内层和外层即使同名，也有不同 ID。

编译时的作用域栈不等于运行时的调用栈。前者帮助确定名字绑定，通常在编译结束后不再需要；后者为每次函数调用保存参数、局部值和返回位置。递归函数的同一个 localId 会出现在不同调用帧中，因此不会相互覆盖。这个连接将带我们进入字节码和虚拟机章节。

10.10 实验、练习与验收#

先对遮蔽例子运行 --check，再执行并核对11、10。然后分别加入下面的错误，每次只改一项：同层第二次 let x、x = true、if (x)、调用不存在函数、少给一个实参、遗漏某一分支的 return。预期它们在执行之前被拒绝。

练习一：false && (1 / 0 == 0) 为什么可以通过类型检查，却不应该在执行时除零？

查看答案

右侧除法的两个操作数都是int，比较结果是bool，逻辑两端类型也匹配，所以静态类型正确。但左侧false已经决定逻辑与结果，语言规定不求值右侧，因此除法不会发生。优化器也必须保留这个可达性语义。

练习二：一个 if 的 then 分支返回，else 分支先打印再返回，整个 if 是否必返回？

查看答案

是。else 块虽然以普通语句开始，但随后返回，正常路径不会离开该块；两个分支都必返回，所以整个if必返回。相反，没有else时，条件为false的路径仍能继续。

练习三：为什么参数与最外层函数体不各自建立一个可随意遮蔽的作用域？

查看答案

这是语言约定。参考语言规定二者同层，从而拒绝紧接参数的同名let；额外嵌套块才允许遮蔽。另一门语言可以规定不同，但符号表实现必须与自己的规范一致，不能由压栈位置偶然决定。

本章验收：能画出嵌套环境，给每个名字使用标出声明来源，独立推导表达式类型，并对结构化控制流判断是否可能落到函数末尾。你现在已经拥有能理解并拒绝错误程序的前端，下一步是把正确程序翻译成可以执行的指令。
