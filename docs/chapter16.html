16 优化：首先证明程序行为没有改变 ​

学习目标与实验边界 ​

本章是扩展实验，现有主线编译器没有对外承诺完整优化流水线。前置是 CFG、数据流和 SSA。你将学会常量折叠、传播、死代码消除、公共子表达式、循环优化，并知道哪些看似显然的变换在检查型整数与短路语义下并不成立。

优化的目标可以是运行更快、代码更小或编译更快，三者并不总一致。先建立正确性契约和可重复的测量，再讨论某个 pass 是否“更高级”。优化器不是一堆字符串替换规则，而是在前提成立时进行的语义保持变换。

常量折叠与常量传播 ​

折叠把 3+4 变成 7；传播根据已知定义，把后续 x 替换成它的常量值。两者配合，x=3; y=x+4 能得到 y=7。SSA 中只需沿唯一定义追踪，但有 φ 时还要合并路径信息。

y0 = add x0, 4            y0 = 7

常量求值必须调用与运行时一致的算术规则。若 2147483647+1 原来应该报溢出，就不能在编译器宿主中使用 int32 算完再得到任意值。对 Sprout 现有的运行时错误契约，安全做法是保留这次运算，或在原来会执行的位置生成显式 trap；不能悄悄改成回绕，也不能把错误无条件提前到编译阶段。尤其 false && (2147483647+1==0) 的右边不会执行，不能因扫描到常量溢出就拒绝它。如果另行设计“某些常量错误在编译期必须诊断”的语言规则，需要先改规范，再讨论这种额外诊断策略。

合并分支时的信息格 ​

对每个值记录三种状态：尚未获得信息、已知常量 c、不是单一常量。两个相同常量合并仍是该常量；不同常量合并则不是常量。循环需要迭代，不能第一次看到 φ 的一个输入就永久决定结果。

稀疏条件常量传播还追踪边是否可执行。若条件被证明为 true，就只让对应边进入分析，另一条不可执行路径中的不同常量不应污染结果。注意“尚未证明可执行”和“永远不可执行”不是一开始就能等同的结论，算法需要单调地更新信息。

死代码消除的核心是可观察行为 ​

若 t 的结果无人使用，t=copy 3 通常可以删除；t=call f() 却不能仅因 t 不使用就删除，因为 f 可能打印、报错或不终止。Sprout 算术会检查溢出与除零，所以 t=1/0 的结果即使不用，也有可观察错误，不能当成纯粹无效计算直接删掉。

这段程序不能被优化成只打印 7。可在 IR 中明确区分纯且不会失败的运算、可能 trap 的检查运算、具有副作用的调用。分析若能证明除数非零且不会溢出，才有机会把某次检查运算当作可删除的纯计算。

一个简单 DCE 保留现有控制流，把所有终结指令（包括条件分支）、print、可能失败和有副作用的指令作为根，反向标记其数据依赖，再删除未标记的纯指令。分支条件也是终结指令的操作数，不能因为它不参与最后的数字结果就删除。更激进地删除控制流还需要控制依赖、终止行为等额外分析，不属于这个入门版本。只做“引用计数为零就删”时还要考虑循环依赖和 φ，标记清扫更容易解释。

公共子表达式与内存别名 ​

若 a、b 的值没变，而且前一次运算的定义支配后一次使用，重复 add a,b 可以复用已有结果。这里复用的是当前路径上已经算出的值，不能凭空把可能报错的运算提前到原来不执行它的路径。SSA 名字使输入是否相同容易判断：相同操作码、类型、输入值和相关语义标志，可以形成一个键，但“键相同”不代替支配检查。两个互斥分支里的同形表达式，不能直接让右分支使用只在左分支定义的临时值。交换律允许 add 的输入规范化，但 sub 不允许。

内存读不能简单照搬这条规则：x=load p; store q,1; y=load p 中，若 p、q 可能指向同一位置，第二次 load 可能不同。源语言尚无指针时可以暂不处理；一旦增加数组与引用，就需要别名分析、内存效果或 MemorySSA 等模型。写“所有相同文字的表达式都合并”会产生错误代码。

循环优化为什么需要更多证明 ​

循环不变代码外提尝试把每轮都相同的计算放到循环前。但 while (false) { x=1/0; } 原来不除零，外提就改变行为。即使表达式输入在循环中不变，也要证明提前执行不会新增错误、内存访问或副作用。

归纳变量与强度削弱可把某些重复乘法变成增量，但检查型整数可能使中间溢出的时机改变。循环展开会增加代码体积；向量化还需证明各次迭代不存在破坏性的依赖。资料库中循环归纳表达式、程序依赖图与多面体相关书目，适合在这些基本证明习惯建立后继续读。

实验：一条规则配一个反例 ​

在纸上为每条变换写“输入模式—前提—输出—反例”。例如 x+0→x 对合法 int32 x 成立；0*x→0 只有在求 x 的过程没有必须保留的行为时才能删去 x 的求值；(x+1)-1→x 在检查型整数下会改变 x 为最大值时的溢出行为。

为一个手工三地址函数实现仅处理安全常量的折叠。每次变换后运行第 13 章验证器，输出变换前后 dump，再用小解释器枚举小范围输入比较结果、错误类别与打印序列。不要只比较最终返回数字。

常见错误、练习与验收 ​

练习一：false && dangerous() 能否直接折叠？练习二：x/x→1 需要哪些前提？练习三：为什么在可达性清理后重新做 DCE 可能删除更多指令？

参考答案

第一题可以把整个表达式折为 false，因为右侧按短路规则原本就不执行；不能因此顺便删除左侧本来必需的副作用。第二题至少要证明 x 非零并保留 x 原有求值行为；值已命名与表达式还未求值是不同场景。第三题不可达块删除后，某些值失去最后一个使用者，新的死值会暴露。验收需要正常、错误、短路与零次循环四类用例，并在每个 pass 后验证 IR。
