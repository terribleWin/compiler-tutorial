CHAPTER 18 / 后端

18 ABI、汇编、链接与运行时内存#

学习目标与前置知识#

本章是机器后端与运行时的扩展实验。第 17 章的 C++ 目标路线已经借助宿主完成这些环节；本章解释被宿主工具代劳的工作。目标是看懂调用约定，区分汇编/目标文件/可执行文件，理解栈与堆的生命周期，并能设计最小的标记清扫垃圾收集实验。

ABI 是程序之间的接口契约#

ISA 规定处理器能执行什么指令；ABI 规定函数参数放哪里、返回值放哪里、哪些寄存器需保存、栈怎样对齐、对象怎样布局。同一指令集可有不同 ABI。Windows x64 的规则不能直接套到 Linux x86-64；RV32 与 RV64 也不能仅把寄存器名复制过去。

以标准 RISC-V 整数调用约定作例子：a0—a7 用于参数，a0、a1 也用于相关返回值；t 寄存器是临时寄存器；s 寄存器若由被调函数修改，返回前需恢复；ra 保存返回地址。sp 是栈指针。具体平台与 ABI 变体应查对应版本的规范，不能把这个教学表当作所有环境的完整规则。RISC-V psABI 规范 是正式依据。

调用者保存与被调用者保存是责任分配，不是说某个寄存器永远不能改变。调用者若有跨调用仍需使用的 t 值，要自己保护；被调用者使用 s 值则要保护调用者原来的值。

栈帧、序言与尾声#

一般函数的序言预留栈空间、保存需要保护的寄存器；尾声恢复它们并释放空间。帧中可能有返回地址、保存寄存器、局部溢出槽和调用其他函数时的参数区。栈指针通常向低地址移动，但“局部变量在源码里的顺序”不必等于内存顺序。

下面是 RV64 的一个教学叶函数，输入 a0，加一后返回；它不展示 Sprout 溢出检查，因此只用于观察 ABI：

# 输入和返回都在 a0；此教学函数没有栈帧。add_one:    addi a0, a0, 1    ret

叶函数不调用别人，常可省去保存 ra。非叶函数调用别人会改写 ra，必须保护返回路线。对标准 RISC-V ABI，栈对齐有明确要求，不能只按“我用几个字节就减几个字节”设计。不要将上面的无检查函数当成 Sprout int32 加法的完整实现。

从汇编到可执行文件#

汇编器把助记符转换成指令编码，并输出目标文件。此时外部函数地址还未知，可在重定位项中记录“这里需要链接器修补”。链接器合并多个目标文件和库，解析符号，安排段地址，处理重定位，最终得到可执行文件或共享库。

生成的程序调用 print 运行时却没有链接实现时，会出现未定义符号；同一外部函数定义两次则可能重复定义。两者都发生在链接阶段，与解析源语言时“变量未声明”不是同一问题。入口函数也不一定直接就是操作系统最先跳入的位置，通常还有平台启动代码负责运行时初始化。

用 C++ 目标路线可观察这些阶段：

g++ -std=c++11 -S program.cpp -o program.sg++ -std=c++11 -c program.cpp -o program.og++ program.o -o program

Windows 运行文件名可使用 program.exe。不同工具链的汇编语法和目标格式不同，重点是知道每一步输入输出，不要要求本机产物一定是 ELF；Windows 常见 PE/COFF，macOS 常见 Mach-O。

运行时做什么#

运行时是编译后程序仍需要调用的服务：打印、分配、边界检查、异常支持、垃圾收集等。即使自制语言很小，也至少需要输出与受控错误。Sprout 的生成 C++ 目标把必要支持随代码输出，便于独立编译；更大型项目可以把稳定运行时单独编成库。

FFI 允许自制语言调用外部语言函数，但必须处理类型宽度、字符串编码、对象所有权、异常边界与 ABI。不能把任意 C++ 对象直接当成 C ABI 的结构传出去。一个合适的首个 FFI 实验是接入 extern "C" 的纯整数函数，再逐步增加字符串与缓冲区。

栈、堆与逃逸#

局部调用帧通常随返回销毁；返回后还要存活的对象不能指向已经销毁的帧。闭包捕获局部变量、函数返回字符串、多个对象共享同一数组，都可能需要堆分配或其他延长生命周期的机制。

宿主 C++ 的 unique_ptr 可以管理编译器 AST，并不自动解决源语言对象的所有权。编译器运行时的 AST 生命周期，与编译出来的程序中字符串生命周期，是两套不同的问题。先区分它们，才不会误以为“实现用了智能指针，所以自制语言就已经支持安全内存”。

最小标记清扫实验#

若扩展语言加入堆对象，可先实现停止世界的标记清扫。每个对象带标记位、字段与链表链接。分配失败或达到阈值时，从根集合出发，遍历对象引用并标记；再扫描全部对象，回收未标记者，清除存活者标记等待下次。

根包括活动帧中仍可达的引用、全局变量与运行时临时持有的引用。遗漏根会错误回收活对象，多报根通常只会让垃圾暂时保留。原生代码后端还需知道引用被分配在哪些寄存器和栈槽，常用栈映射与安全点配合。

引用计数是另一种权衡：最后一个引用释放时即可回收，但普通引用计数不能自行回收环。移动收集器可压缩堆和改善局部性，却需要更新所有指针。并发收集还要处理程序修改引用与收集器遍历之间的一致性；不要在第一个 GC 实验中同时加入移动和并发。

练习、常见错误与验收#

练习一：解释非叶函数为什么通常要保存 ra。练习二：画出 A→B→A 的对象环，说明引用计数为何留下它，而追踪收集能回收。练习三：调用外部函数后一个值变了，该优先检查什么？

参考答案

调用其他函数会写 ra，若不保存就丢失自己应返回的位置。环中每个对象都持有另一个，引用计数不降为零；若根无法到达它们，标记清扫都不会标记，可一并回收。跨调用值变化应先核查 caller-saved/callee-saved 约束、栈对齐和参数布局。验收要区分编译、汇编、链接和运行错误，GC 实验则需验证共享对象、环和活动帧根。
