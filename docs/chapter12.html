12 虚拟机、函数调用与运行时 ​

学习目标与前置知识 ​

本章接着第 11 章解释字节码如何运行。你将理解程序计数器、操作数栈、局部变量、调用帧，以及递归为什么需要每次调用独立保存状态。本章属于可运行主线，请把教学模型与 compiler/src/sprout.cpp 对照；类名和枚举以参考源码为准。

一条指令如何执行 ​

最简单的 VM 有指令数组 code、下一条指令索引 ip、临时值栈 stack。执行循环取出 code[ip]，增加 ip，再按指令修改栈或跳转。先递增再执行是一种约定，也可由每条指令更新 ip，但全套实现必须统一。

cpp
// 教学片段：省略完整指令集与错误处理。
while (!finished) {
    const Instruction ins = code.at(ip++);
    switch (ins.op) {
    case Op::Push: stack.push_back(ins.value); break;
    case Op::Jump: ip = ins.target; break;
    default: executeChecked(ins); break;
    }
}

数组边界检查不能替代完整的 VM 验证。无效跳转、栈下溢、槽位越界应报告内部字节码错误；源码中的除零则是用户程序运行时错误。即使字节码仅由自己的生成器产生，这些检查也能直接定位生成器缺陷。

上段描述更完整 VM 的验证目标。参考实现检查操作数栈下溢，并通过容器边界检查保护局部槽位；它只执行自身在内存中生成的指令，没有完整的不可信字节码验证器，也不支持把 --bytecode 文本重新装载执行。

为什么全局 locals 数组不够 ​

fact(4) 会调用 fact(3)。两个调用都有 n 参数，但必须分别保存 4 和 3。若共享同一个槽位，内层会覆盖外层 n，返回后乘法就读错值。每次调用必须建立一张帧：记录函数、局部槽位和返回位置。

帧可以拥有独立操作数栈，也可只记录共享栈的基址。无论如何，返回时都要恢复调用前边界，只留下返回值。词法作用域与帧不是一回事：一个函数中的多个花括号可以共享调用帧；递归调用同一个函数却需要多张帧。

参考代码使用递归的 C++ VM::call 表达这个模型：每次调用创建自己的 locals、stack 和 ip，主调函数的返回位置保存在宿主调用状态中，没有额外定义名为 Frame 的类。理解后再把它改写成显式帧数组，是一个合适的扩展练习。

值表示与类型检查的分工 ​

前端应拒绝 true + 3，VM 可以利用已验证信息。底层仍需统一的值表示，例如类型标签加整数/布尔载荷。C++11 用 enum class 和结构体即可，不必为实现一台 VM 先学习复杂模板。C++17 可以换成 variant，但这种宿主实现重构不能改变 Sprout 类型规则。

内部若用 0/1 保存 bool，也不意味着源语言允许 bool 自动参与加法。打印 bool 时同样要按规范输出，不能偶然受输出流格式状态影响。这里展示了编译器的一条基本原则：目标机器的方便表示与源语言允许的行为必须分开考虑。

明确整数语义 ​

C++ 有符号溢出不能靠“先用 int 算完，再检查结果”可靠检测。对 int32 加减乘先扩展到 int64，检查范围后再转换。除法先检查除数为零和最小整数除以 -1；一元取负也要检查最小整数。下面是独立的教学片段，真实项目还应带上源码位置：

cpp
std::int32_t checkedAdd(std::int32_t a, std::int32_t b) {
    const std::int64_t r = std::int64_t(a) + std::int64_t(b);
    if (r < std::numeric_limits<std::int32_t>::min() ||
        r > std::numeric_limits<std::int32_t>::max()) {
        throw std::runtime_error("integer overflow");
    }
    return static_cast<std::int32_t>(r);
}

需要包含 cstdint、limits、stdexcept。VM 与生成 C++ 的运行时必须遵守同样规则，不能一条路径报错而另一条路径悄悄回绕。后面引入 LLVM 时也必须保留检查，不能直接把源算术换成任意带优化标记的整数指令。

Sprout 的除法向零截断，余数与被除数同号：-7 / 3 得到 -2，-7 % 3 得到 -1。注意 -2147483648 / -1 越界，而 -2147483648 % -1 的结果是 0；参考实现先扩展到 int64 运算，避免直接执行宿主 int32 的危险组合。字面量的特殊规则是允许直接写 -2147483648，但不允许单独的 2147483648 或 -(2147483648)。

执行保护与位置映射 ​

教学 VM 为执行步数和调用深度设置上限，使死循环与错误递归能受控退出。预算是执行器保护，不是源语言的数学结果。不同后端的指令数量不同，因此不应直接比较它们的精确步数。

每条可能失败的指令都应关联源码位置。10 / (x-x) 失败时，报告源码中的除法行比报告第 87 条指令更有用。进一步可记录调用链 main→f→g，让 g 的除零能沿调用关系被理解。转换表示时保留位置，是为将来调试器与优化后诊断打基础。

初学者常问为什么不直接让宿主抛出所有异常。因为宿主的数组越界、内存耗尽、栈溢出并不等同于源语言已定义的运行时错误；编译器应在边界处建立清晰解释，避免把内部 bug 混成“用户程序写错”。

常见错误与练习 ​

  • 递归返回后外层参数变了：局部变量被共享或错误复用。
  • 两参数函数结果反了：实参压栈与形参取值顺序不一致。
  • 每次调用残留一个值：返回时没有恢复栈基址。
  • 无限递归使进程崩溃：检查发生得太迟，或根本没有深度上限。

手算 fact(3) 的帧创建与销毁；写一个自调用函数检验受控错误；用 false && (1/0==0) 检验短路。

参考答案与验收

帧依次为 main、fact(3)、fact(2)、fact(1)，返回值依次为 1、2、6，随后 main 返回。自调用函数应触发深度或预算错误；短路例子得到 false 而非除零。再测试两个连续调用和嵌套调用不污染局部量，以及减法/除法操作数顺序，才能验收调用机制。
