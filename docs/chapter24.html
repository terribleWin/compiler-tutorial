第24章 AI 编译器：张量程序、调度与异构执行 ​

本章位置、目标与前置 ​

第23章沿着“模型怎样进入部署环境”建立整体路线。本章把镜头推近到一个计算区域：一项矩阵运算怎样变成循环，循环怎样分块、融合、向量化，最后怎样交给 CPU、GPU 或其他加速设备执行。第25章再研究如何自动寻找优化策略。本章先让你知道每一个候选策略实际在改变什么。

前置知识是第13章的 IR、第14章的依赖分析、第16章的优化正确性和第18章的内存。你不需要已经会训练神经网络，也不需要拥有 GPU。先完成本章不依赖第三方库的 Python 实验，再根据兴趣选择 TVM 或 MLIR 扩展。

本章属于进阶扩展。当前 Sprout 只有 int32 与 bool，尚未实现张量类型、浮点类型、张量调度器或异构运行时。本章的 Python 是独立的算法实验，不通过 Sprout 执行；TVM、MLIR 和 IREE 是可选工具路线，没有把未在本机运行的工具示例计入已验证结果。主线 C++11/14/17/20 兼容承诺仍指 Sprout 工程，不表示这些外部工具的当前开发库可以都用 C++11 构建。

学习完成后，你应该能给一个矩阵乘写出迭代空间，区分程序含义与执行调度，解释融合与分块的合法性，计算基础算术强度，并设计同时核对数值正确性、执行时间和编译开销的实验。

24.1 张量不是神秘的新对象 ​

张量在这里可以先理解为有形状、元素类型和存储约定的多维数据。一个 M×K 的二维张量，就是能通过两个下标访问的矩阵；三维可能表示一批矩阵；更高维也依靠同样的下标规则。维数叫 rank，各维长度组成 shape，元素可能是 float32、整数或其他明确的数据类型。

“二维”不表示一定存成二维链表。一个行优先的连续 M×K 矩阵，可以放在一维缓冲区里，逻辑元素 A[i,k] 的元素偏移为 i*K+k。若每个元素4字节，字节地址再乘4。带步长的视图则可能使用 base + i*s0 + k*s1。形状描述能访问哪些逻辑元素，布局和步长描述这些元素存在哪里，二者需要分开。

对矩阵乘，设 A 形状为 M×K，B 为 K×N，输出 C 为 M×N：

text
C[i,j] = sum(A[i,k] * B[k,j], k=0..K-1)

空间轴：i = 0..M-1，j = 0..N-1
归约轴：k = 0..K-1

固定 i、j 后，k 方向上的多项贡献合成同一个输出，称为归约。不同 i、j 通常写不同元素，因此容易分配给不同执行单元；不同 k 却更新同一个元素，不能不加处理地并发写入。辨别空间轴和归约轴，是理解张量调度的第一步。

24.2 计算图与张量程序各保存什么 ​

计算图可以写成 Y=MatMul(A,B)、Z=Add(Y,bias)、O=ReLU(Z)。它保留运算之间的数据依赖，适合做跨算子融合、常量传播、形状推导和设备划分。但一个 MatMul 节点还没有说明线程如何分工、哪些数据放进缓存、一次算几个输出。

张量程序把节点进一步展开为循环、索引、缓冲区和计算区域。下面是语义清楚的基准程序，不是性能最优程序：

text
for i in 0..M-1:
    for j in 0..N-1:
        accumulator = 0
        for k in 0..K-1:
            accumulator += A[i,k] * B[k,j]
        C[i,j] = accumulator

高层图与低层张量程序不是只能二选一。一个编译模块可以同时包含图函数和已经展开的局部核函数。高层保留模型结构，局部区域逐步降低到机器可执行的形式。过早把所有结构拆成裸指针和标量循环，会丢失“这是矩阵乘”“这是可独立并行的轴”等对优化很有帮助的信息。

读现代框架时，把“图优化负责什么”“一个张量区域内部怎样优化”“运行时怎样发起执行”分成三个问题。否则看到三个不同层的调度器都叫 schedule，很容易误以为它们在做同一件事。

24.3 程序含义与 schedule：算什么，怎样算 ​

本章把 schedule 译作调度方案：它规定循环怎样分块、换序、映射到线程、放置临时缓冲和使用向量操作。原程序规定哪些输入决定哪些输出，调度在合法前提下改变执行组织。调度本身不拥有“为了更快可以随意改变结果”的许可证。

例如把外层 i 循环切为大小4的块：

text
for io in 0..ceil(M/4)-1:
    for ii in 0..3:
        i = io*4 + ii
        if i < M:
            执行原本第 i 行的工作

这是 split。新增循环必须覆盖每个合法 i，且不重复、不漏算，也不能越界。M 不是4的倍数时，尾部条件是正确性的一部分。只用维度整齐的测试，会让错误调度“看起来一直正确”。

再把 i,j,k 换成 i,k,j：每次取出一个 A[i,k]，连续更新 C 的一段行，同时连续读取 B 的一段行。它可能改善局部性，但必须将 C 初始化一次，并保证每个输出仍按需要累加所有 k。若数组有别名、循环体有输出或共享可变状态，换序还要重新做依赖与效果检查。

特别注意归约顺序。对本章的精确整数模型，换一种累加顺序也能得到相同数学整数；对浮点数，改变归约树可能改变舍入结果。所谓“调度保持语义”，始终以当前数值契约为条件。

24.4 完整实验：三个矩阵乘与一次融合 ​

将下面整段保存为 tensor_schedule_lab.py，使用 Python 3 运行。项目也提供同内容文件 compiler/experiments/tensor_schedule_demo.py，在 compiler/ 目录可直接执行 python experiments/tensor_schedule_demo.py。只依赖标准库，正整数维度和矩形列表是本实验输入契约。测试包含1×1、非整除尾块和长方形，避免只验证漂亮的方阵。

想先看见分块过程，可以打开本站的张量分块实验室，选择 N=4 或8、tile=1/2/4，逐步执行一个 i0,j0,k0 块，观察 A、B 的输入区域和 C 的累加区域。完成全部步骤后，再逐元素对照参考结果。页面中的 2*N³/T 是理想输入读取次数模型，不是实际缓存流量或真实硬件性能，不能代替本章后面的测量。

代码先用精确整数排除浮点误差，使你专注于索引和调度。Python 整数是任意精度，不是 Sprout 的 int32，也不是设备上的 float32。随后单独观察浮点归约差异。运行时间只用于练习测量流程，不用于声称某种设备后端更快。

python
import math
import platform
import statistics
import time


def shape(matrix):
    if not matrix or not matrix[0]:
        raise ValueError("this lab requires positive dimensions")
    width = len(matrix[0])
    if any(len(row) != width for row in matrix):
        raise ValueError("ragged matrix")
    return len(matrix), width


def dimensions(a, b):
    m, k = shape(a)
    kb, n = shape(b)
    if k != kb:
        raise ValueError("inner dimensions do not match")
    return m, k, n


def matmul_ijk(a, b):
    m, k, n = dimensions(a, b)
    c = [[0 for _ in range(n)] for _ in range(m)]
    for i in range(m):
        for j in range(n):
            acc = 0
            for r in range(k):
                acc += a[i][r] * b[r][j]
            c[i][j] = acc
    return c


def matmul_ikj(a, b):
    m, k, n = dimensions(a, b)
    c = [[0 for _ in range(n)] for _ in range(m)]
    for i in range(m):
        for r in range(k):
            av = a[i][r]
            for j in range(n):
                c[i][j] += av * b[r][j]
    return c


def matmul_tiled(a, b, bm=4, bk=5, bn=3):
    if min(bm, bk, bn) <= 0:
        raise ValueError("tile sizes must be positive")
    m, k, n = dimensions(a, b)
    c = [[0 for _ in range(n)] for _ in range(m)]
    for i0 in range(0, m, bm):
        for j0 in range(0, n, bn):
            for r0 in range(0, k, bk):
                for i in range(i0, min(i0 + bm, m)):
                    for r in range(r0, min(r0 + bk, k)):
                        av = a[i][r]
                        for j in range(j0, min(j0 + bn, n)):
                            c[i][j] += av * b[r][j]
    return c


def matmul_bias_relu_fused(a, b, bias):
    m, k, n = dimensions(a, b)
    if len(bias) != n:
        raise ValueError("bias width does not match output")
    out = [[0 for _ in range(n)] for _ in range(m)]
    for i in range(m):
        for j in range(n):
            acc = 0
            for r in range(k):
                acc += a[i][r] * b[r][j]
            out[i][j] = max(acc + bias[j], 0)
    return out


def inputs(m, k, n):
    a = [[(i * 17 + r * 3) % 11 - 5 for r in range(k)]
         for i in range(m)]
    b = [[(r * 7 + j * 5) % 13 - 6 for j in range(n)]
         for r in range(k)]
    return a, b


def median_seconds(fn, a, b, repeats=7):
    fn(a, b)  # warm-up, outside the timed samples
    samples = []
    for _ in range(repeats):
        start = time.perf_counter()
        result = fn(a, b)
        samples.append(time.perf_counter() - start)
        assert shape(result) == (len(a), len(b[0]))
    return statistics.median(samples)


def main():
    checks = 0
    for dims in [(1, 1, 1), (5, 7, 6), (9, 5, 11)]:
        a, b = inputs(*dims)
        reference = matmul_ijk(a, b)
        assert matmul_ikj(a, b) == reference
        checks += 1
        assert matmul_tiled(a, b) == reference
        checks += 1
        bias = [j - 2 for j in range(dims[2])]
        unfused = [[max(value + bias[j], 0)
                    for j, value in enumerate(row)]
                   for row in reference]
        assert matmul_bias_relu_fused(a, b, bias) == unfused
        checks += 1
    print("correctness checks:", checks)

    a, b = inputs(5, 7, 6)
    print("checksum 5x7 @ 7x6:", sum(map(sum, matmul_tiled(a, b))))
    x, y, z = 1e16, -1e16, 1.0
    print("reduction order:", (x + y) + z, x + (y + z))
    print("fsum reference:", math.fsum([x, y, z]))

    print("python:", platform.python_version())
    a, b = inputs(24, 20, 28)
    for fn in [matmul_ijk, matmul_ikj, matmul_tiled]:
        elapsed = median_seconds(fn, a, b)
        print(fn.__name__, "median_ms=", format(elapsed * 1000, ".3f"))


if __name__ == "__main__":
    main()

24.5 逐行理解循环换序的收益与成本 ​

ijk 版本把一个输出保存在局部 acc 中，完成全部 k 后写回一次。它在 B 上沿列取数；在行优先连续存储中，相邻两次 B 访问通常隔着一整行，局部性可能较差。

ikj 版本将 A[i,r] 暂存在 av，再沿 j 连续读取 B 的一行，更新 C 的一行。A 的同一元素可以在多个输出间复用，但 C 的更新出现在内层，源代码层面的读写次数增多。真实机器可能把 C 的一个小区域留在缓存或寄存器，因此“源码访问次数”不等于“主存传输次数”。编译器需要根据数据大小和目标资源继续调整。

本实验使用 Python 列表：每行是独立对象，整数也不是紧密排列的32位数组，而且每次循环仍有解释器开销。因此我们没有真的生成向量指令，也没有精确控制缓存。把 Python 调度的时间直接写成“张量编译器加速了几倍”会混淆算法演示和机器代码性能实验。

这层区分也解释了为什么性能优化需要保留多种表示。高层知道 i,j 独立；张量层知道相同 tile 的数据能复用；机器层才知道寄存器数、向量宽度和指令限制。每层都只保留自己知道的信息，后面的决策才有可靠依据。

24.6 分块如何利用内存层次 ​

内存层次可以先按“容量越小通常越靠近计算单元”理解：寄存器、不同层级缓存、设备显式局部存储、主存或设备全局内存。不同设备的层次名称与访问机制不完全相同，不能把 CPU 缓存和所有加速器片上存储视作同一种东西。

矩阵乘中，一个 BM×BN 输出块需要反复累加。每个 k 块读入 BM×BK 的 A 和 BK×BN 的 B，让这些数据在近处被多个乘加复用。若三块都按 float32 保存，一个简单的工作集估算为：

text
bytes ≈ 4 * (BM*BK + BK*BN + BM*BN)

BM = BK = BN = 32 时：
bytes ≈ 4 * (1024 + 1024 + 1024) = 12288 字节 = 12 KiB

这是容量估计，不是“放进去就一定快”的证明。还需要考虑并发块数量、缓存关联冲突、对齐、其他活跃数据、双缓冲，以及输出累加器是否占用太多寄存器。块很大可能增加复用，也可能挤爆资源；块很小调度开销与边界比例又会增加。

内外两层分块也很常见：大块面向缓存，小块面向寄存器或向量操作。将整个 C 块一直保存在局部累加器，通常比每次从远处重新读写更有潜力；但这是比 Python 列表实验更低层的实现任务，需要明确物理表示后再测量。

24.7 布局、向量化与尾部掩码 ​

布局变换改变逻辑下标到物理地址的映射。转置 B 可以让原来按列的访问变成连续读取，但转置自身需要计算与存储。若 B 会被重复使用很多次，预打包成本可能划算；只算一次的小矩阵可能反而更慢。布局变换也可以作为视图表达，但视图不保证原本不连续的数据突然变连续。

向量化把多个独立标量操作组织成一条或少量向量操作。若一条向量含8个元素，j 轴可以拆成外层块号和8个相邻位置；N 不是8的倍数时，最后一组要使用掩码或标量收尾。掩码必须同时保护访存与有效计算，不能先越界读取再把结果遮掉。

“连续”也不是唯一目标。多个线程怎样共同访问内存、数据是否适合设备指令的块布局、转换是否产生额外搬运，都影响最终效果。某些布局更适合乘法单元，却让后继算子读数困难。选择布局时要看一个区域乃至整条图的收益，而不是只看单个算子的最好数字。

归约轴上的向量化需要把向量部分结果合并，这可能改变加法分组；空间轴向量化则通常可以让每个输出维持原来的 k 顺序。两种情况都叫向量化，但数值语义需要分别分析。

24.8 算子融合：消除中间结果之前先看使用者 ​

独立执行 MatMul、Add 和 ReLU 时，可能先写完整的 Y，再读 Y 写 Z，再读 Z 写 O。融合 epilogue 可以在一个输出块计算完成后立即加偏置、做 ReLU，最后只写 O。实验中的 matmul_bias_relu_fused 就是最简单的逐元素出口融合。

融合的关键不是把函数名拼在一起，而是改变中间结果的产生与消费位置。假设 Y 还被另一条支路读取：

text
Y = MatMul(A, B)
O = ReLU(Y + bias)
P = AnotherConsumer(Y)
1
2
3

此时不能直接删除 Y。可以继续保存它、只融合其中一条支路、融合全部兼容消费者，或在代价合适时重算一部分。重算会增加算术；保存会增加流量；扩大融合区域会增加寄存器和局部存储压力。多使用者是图级决策必须看到的信息。

融合还要尊重效果。随机数、打印、设备同步、写入可能别名的缓冲区、显式异常或检查不能随意复制、删除或越过。即使每个节点看起来像数学函数，也要核对其真实契约。普通稠密算子可以依赖纯函数模型；含状态操作的图需要额外效果与顺序信息。

对于归约，不要把 ReLU 推进每一次累加。若贡献依次是-2和1，先完整求和再 ReLU 得0；每次更新都截到非负会变成1。正确出口应位于全部 k 累加完成之后。这是“融合合法”与“融合位置正确”之间最直观的区别。

融合也可能受跨线程同步限制。如果一个消费者需要所有线程组都完成的全局结果，不能仅靠组内屏障就与生产者放入同一个普通核。过度融合还可能让更多线程争用访存、让中间值溢出到慢存储，最终比多个小核更慢。

24.9 浮点归约：精确、近似与可重复 ​

数学实数加法满足结合律，有限精度浮点加法通常不满足。实验中的 1e16、-1e16、1.0 用 Python 的浮点表示就能观察到不同分组产生不同结果。这个例子说明变化的来源，并不代表 Python 浮点等同于设备 float32，也不承诺所有数值误差都能用一种公式解决。

张量后端必须明确输入、乘积、累加和输出的精度。输入可以较低精度而累加使用更高精度；融合乘加可能只舍入一次，与先乘后加不同。并行树形归约、向量化、分块和原子累加还可能改变累加次序与可重复性。

严格语义下，不能把这些变化当作无条件等价。若应用允许误差，应明确绝对误差与相对误差、NaN/无穷/有符号零策略、是否要求每次运行相同，再选择允许的优化。判断 abs(actual-reference) <= atol + rtol*abs(reference) 是常见起点；参考值接近零、包含特殊值或误差被后续放大时，还需要补充规则。

对整数也要说明范围和溢出。Python 实验的精确整数等价验证，不能直接证明 int8 输入、int32 累加或 Sprout 检查型整数在任意规模下都等价。若每项都在范围内但部分和会溢出，换序仍可能改变是否触发检查。

24.10 并行、同步与异构边界 ​

CPU 上可以把不同输出行或块分给工作线程，每个线程只写自己的区域，减少数据竞争。共享缓存、线程启动、任务粒度和相邻元素落在同一缓存行造成的争用仍会影响收益。不是循环迭代数多就一定适合创建同样多的线程。

GPU 或其他大量并行设备通常将工作组织成网格和线程组。一个组共同处理输出 tile，从全局存储搬入共享区域，完成同步，再执行局部计算。若复用同一缓冲区装下一块数据，往往还要保证上一轮读完，避免新数据覆盖旧数据。屏障参与者与条件分支必须满足目标的执行规则；只有部分线程抵达一个要求全组参与的屏障，可能导致错误或无法前进。

同一个 C 元素若被多个执行单元沿 k 分工，必须使用私有部分和再归约、适当原子操作或其他合法协作方案。简单地让多个线程都做 C[i,j] += ... 会形成数据竞争。原子加法解决更新丢失，也不自动保证浮点顺序确定或速度理想。

异构执行还包括主机与设备之间的数据驻留、拷贝、命令提交、事件与完成通知。异步提交成功表示工作已排队，不表示结果可读；CPU 读取输出或复用输入前，需要按运行时依赖关系等待。设备执行的时间、主机等待的时间和整次请求的延迟应分开测量。

将小算子单独放到设备上时，数据搬运和发起执行可能比算术更贵。因此设备划分不仅是“哪个设备单次乘法快”，而是“把哪些相邻运算和数据一起留在什么位置，整体请求才更快”。本章只建立局部调度和运行依赖的边界，模型级部署选择继续参考第23章。

24.11 TVM TensorIR：程序结构与调度轨迹 ​

TVM 的 TensorIR 路线把缓冲区、循环、计算块和轴属性保留下来，让变换能够理解读写区域及归约。调度不是直接编辑最终机器码，而是在结构化张量程序上依次做 split、reorder、计算位置调整与归约拆分等操作，再检查变换是否合法。TensorIR 官方介绍给出当前表示边界。

版本需要特别留意：2026年11月6日核对的官方最新文档，已将原先的 tir 职责拆到 tirx 与 s_tir。当前变换教程中的调度对象使用 s_tir.Schedule，计算块查找出现 get_sblock。旧文章里的 tvm.tir.Schedule、get_block 和 TVMScript 导入方式，不能不核对版本就直接当作今天可执行的命令。

建议的可选实验是在独立环境打开与你安装版本匹配的官方教程，先运行其完整原例，再做下面三次小改动：打印初始模块；只对一个空间轴分块后打印模块；换序后打印调度轨迹。每次核对输出值、形状、尾部处理与归约初始化。最后再把 ReLU 的消费位置靠近矩阵乘结果，检查是否仍在归约完成后执行。官方 Transformation 教程包含当前版本的完整代码。

本章未在本机安装或执行 TVM，因此这里提供的是可复现的操作路线与验收项，不是一次已完成的 TVM 性能测试。先固定工具版本和完整官方示例，再迁移本章小矩阵，能把 API 兼容问题与调度算法问题分开。

24.12 MLIR 与 IREE：逐层表达和执行 ​

MLIR 的 linalg 层适合保留结构化算子、索引映射、空间与归约迭代器；affine 层能表达受约束的索引和循环关系，支持相应分析与变换；vector 层表达向量值和向量操作。它们是可以组合的表示工具，不是一条所有项目都必须按完全相同顺序通过的固定流水线。linalg、affine和vector的官方定义分别说明其约束。

张量值与可变内存引用也要区分。高层张量操作可以产生新的逻辑结果，bufferization 决定如何将其映射到实际存储及合法复用。不能因为两个张量形状相同，就断定它们可以原地写入同一地址。存在后续使用、别名和并发访问时，复用必须有证明依据。

IREE 在编译与运行时之间组织可调度的计算区域。一个 dispatch 可以面向 CPU 任务系统，也可以面向设备核；它不简单等同于“每个原始图节点发一个 GPU 核”。区域融合、设备代码生成、缓冲区与依赖管理分布在不同层。IREE 的自定义 dispatch 官方样例明确说明这种执行模型。

可选实验先选一个工具栈，而不是同时安装三个。对于 MLIR，先看官方已有结构化矩阵乘示例，找出迭代器类型、索引映射与结果初始化；对于 IREE，先运行与你平台匹配的最小官方模型，再定位生成的 dispatch 区域。保存每层 IR，并把每次改变归结为“图区域变了”“循环调度变了”“存储映射变了”或“运行时依赖变了”。这些外部工具实验同样未在本次本机环境中执行。

24.13 Roofline：先判断可能卡在哪里 ​

Roofline 用一个简单上界帮助理解计算与访存的竞争。设算术强度 I 为“运算次数/跨指定存储边界传输的字节数”，带宽为 BW，峰值计算速率为 P，则粗略可达性能满足：

text
attainable_performance <= min(P, BW * I)
1

一定要说清楚边界：按主存流量计算的强度与按较近缓存流量计算的强度不同。强度分母不是源代码里出现了多少次数组下标；缓存命中、数据复用和写回策略都会影响实际流量。Roofline 是诊断模型，不是自动证明某实现已达到上限的工具。Williams 等人的原始论文介绍了这一分析方法。

矩阵乘常按每个乘加2次浮点运算估算，总量约为 2*M*N*K。若理想地只从远处读 A、B 一次，且 C 从零开始、只写一次，float32 流量下界近似为 4*(M*K+K*N+M*N)。对128方阵，强度约为 2*128^3 / (4*3*128^2) = 21.33 FLOP/byte。这只是理想复用下界；朴素执行可能反复从远处取数，实际强度更低。

逐元素加法每个输出约1次加法，却要读两个float32、写一个float32，理想约 1/12 FLOP/byte，通常比矩阵乘更容易受带宽约束。融合可以减少中间读写，分块可以提高近处复用；二者改善的是模型中的不同成本，不能只用“运算次数少了”解释所有收益。

24.14 怎样测量，怎样计算编译成本摊销 ​

先正确，再计时。固定输入形状、类型、布局、线程数和设备；记录工具版本与构建选项；区分首次编译、首次运行、预热后运行；重复多次并报告中位数及波动。异步设备计时需要在适当边界同步，否则可能只量到了提交命令的时间。

微基准还要说明包括什么：输入准备、布局转换、主机设备拷贝、内存分配、核执行和输出读取。可以分别报告核时间与端到端时间，但必须用同样边界比较两种方案。自动调优在几十次试跑中挑出最好一次后，还应使用独立的重复测量确认，避免把噪声选成“最优策略”。

假设新方案比基线额外编译或搜索2秒，每次执行节约50微秒，只考虑这两项成本时，需要约 2/0.00005 = 40000 次执行才能抵消额外成本。若每次都出现新形状、缓存无法复用，调优可能一直无法摊销；若同形状执行百万次，情况又不同。

缓存键至少要覆盖影响生成代码的形状、类型、布局、目标与相关编译设置。把另一种布局的优化结果误用到当前输入，不只是性能下降，还可能产生错误地址。长期测量应分别记录编译延迟、稳态延迟、吞吐量和峰值内存，不用一个数字代替全部目标。

24.15 常见错误与分阶段调试 ​

结果形状正确但数值错误，先检查下标、尾块与输出初始化；只有特定块大小错误，重点看边界和同步；单线程正确而并行错误，检查写入冲突、部分和及屏障；每次结果略有不同，检查归约顺序与原子更新的数值契约；单核很快但整图变慢，检查转换、拷贝、发起开销和融合区域外的成本。

给每次变换保留前后 IR 或循环清单，使用同一个参考实现比较。不要同时换布局、分块、向量化和线程映射后才看第一次结果。一个手把手可推进的顺序是：精确标量基准、尾块正确的分块、带成本的布局变换、空间轴向量化、输出融合、线程并行、异构传输与同步；每一步都保留旧测试。

24.16 练习、答案与验收 ​

练习一：若 C 的行数为5，BM=4，外层分块有几轮，每轮实际处理哪些行？如果去掉尾部条件会发生什么？

查看答案

两轮。第一轮处理0—3，第二轮只处理4。没有 min 或等价掩码时，第二轮会尝试访问5—7，超出合法范围。尾块是正常输入情况，不是可以忽略的异常。

练习二：为什么实验中的 ReLU 只能在全部 k 贡献累加后执行？再为有两个消费者的 Y 设计两种合法融合策略。

查看答案

逐次 ReLU 会改变归约本身，例如贡献-2、1的最终结果应为0，逐次截断则得到1。多消费者时，可以保留Y给第二条支路并只融合第一条出口，也可以在不改变效果且代价合适时重算局部Y；还可以扩大融合区域，但必须处理资源与同步限制。不能直接删除仍被使用的Y。

练习三：矩阵乘的8个 k 项分给4个线程，每线程处理两项，为什么需要额外归约？浮点结果可能怎样变化？

查看答案

每线程只得到同一输出的部分和，必须将4个部分和合成最终值。若多个线程直接更新共享C会出现竞争；原子或树形归约是不同实现选择。归约分组变化可能改变浮点舍入，因此需要契合应用允许的误差与可重复性规则。

练习四：一次预打包需要3毫秒，每次乘法因此节约30微秒，B 至少复用多少次才开始抵消预打包成本？

查看答案

按简化模型，0.003/0.00003 = 100 次达到持平，超过100次才产生净收益。实际还要考虑存储、缓存失效、形状变化与打包后额外数据移动，不能只比较算术部分。

基础验收是完整 Python 实验的9项相等检查通过，5×7乘7×6的校验和为-15，能解释三种循环组织和非整除尾块。原理验收是为一项融合或换序写出合法性前提、资源成本和至少一个反例。工具扩展验收还要保存准确版本、输入与参考输出、变换前后 IR、数值误差标准，以及计时范围；未实际运行的设备和工具明确标为未验证。
