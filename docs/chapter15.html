CHAPTER 15 / 进阶

15 SSA、支配关系与 φ：一个名字只定义一次#

学习目标与边界#

本章是扩展路线，主线编译器没有现成的 SSA 命令。先会 CFG、前驱后继和集合迭代。目标是手算支配集合，在分支与循环中放置 φ，理解重命名栈，以及为什么离开 SSA 时需要并行复制。

SSA 是 Static Single Assignment，即静态单赋值。每个名字在程序文本中只定义一次；这不意味着循环指令运行时只执行一次，也不意味着源语言变量不能赋值。编译器为每次静态定义分配不同的 IR 名字。

先处理直线代码#

源级赋值          SSA 名字x = 3             x0 = 3x = x + 1         x1 = add x0, 1print x           print x1

读 x1 时无需追问此前哪个分支最后写过 x：定义直接指向 add x0,1。值的使用表也更容易维护。给同一变量所有出现简单加一个固定后缀不行；新名字对应的是定义，不是源码里的拼写。

分支汇合为什么需要 φ#

entry: branch cond, left, rightleft:  x1 = 4; jump joinright: x2 = 6; jump joinjoin:  x3 = phi [x1,left], [x2,right]       print x3

φ 的意思是“根据刚刚从哪条前驱边进入，选择对应的值”。它不是先算两个参数再比较大小，也不是运行时调用名叫 phi 的函数。如果从 left 过来，x3=4；从 right 过来，x3=6。值与前驱必须成对记录，不能靠数组顺序暗中约定。

在这张菱形图中，left 不在所有到 join 的路径上，因此 left 的定义不能直接作为 join 中唯一可用的 x。φ 把这个路径差异显式放到一个新定义中。

支配：所有进入路径都经过谁#

若从入口到 B 的每条路径都经过 A，称 A 支配 B。每块支配自己，入口支配所有可达块。对可达图，可用集合迭代求解：入口的集合只有自己，其他块先初始化为全部可达块，再反复计算。

Dom(entry) = {entry}Dom(B) = {B} ∪ intersection(Dom(P))，P 为 B 的前驱

菱形图中 Dom(left)={entry,left}，Dom(right)={entry,right}，Dom(join)={entry,join}。这里合并用交集，因为要“每条路径都经过”；第 14 章活跃分析用并集，因为问“存在一条路径会读取”。量词不同，集合操作也不同。

直接支配者 idom(B) 是最接近 B 的严格支配者。把它们连起来形成支配树，菱形图中 left、right、join 的 idom 都是 entry。不可达块需要先过滤或单独定义策略，否则空前驱的交集会产生误导。

支配边界与 φ 放置#

A 的支配边界包含这些块 Y：A 支配 Y 的某个前驱，却不严格支配 Y。直觉上，这是“A 所控制的定义和其他路径第一次汇合”的地方。菱形图中 join 属于 left 与 right 的支配边界。

经典构造方法是：对一个源变量，收集它所有定义块；在这些块的支配边界插 φ；新插入的 φ 也算定义，必要时继续沿边界传播。这样得到迭代支配边界。第一版可以在所有可能汇合处放较多 φ，再删除无用者；改进版本结合活跃性，只放在该变量活跃的地方，得到剪枝 SSA。

不要在“每个有两条前驱的块”为“每个变量”都无条件放 φ。这样可能仍能表达程序，但会膨胀并掩盖构造思路；更危险的是放了 φ 却没有为每条前驱提供正确输入。

重命名栈：沿支配树遍历#

为每个源变量维护一个栈。遇到定义就产生新版本并压栈，遇到读取就取栈顶。遍历块时先处理本块 φ 定义，再处理普通指令；然后为每个后继的 φ 填上当前边应传出的版本。递归处理支配树子节点后，弹出本块新增的定义。

这不是沿 CFG 任意深度优先遍历，因为 CFG 可能有回边。支配树无环，栈的进出正好反映哪些定义支配当前使用。对块内普通使用，还需要定义在该使用之前；仅有块级支配不够。

循环例子：φ 可以引用稍后定义#

entry:    jump looploop:    i0 = phi [0,entry], [i1,body]    c = lt i0, 3    branch c, body, exitbody:    print i0    i1 = add i0, 1    jump loopexit:    return 0

第一次从 entry 进入时 i0=0；之后从 body 返回，i0 取上一轮 i1。静态只有一个 i1 定义，但运行时会重复执行。φ 输入的使用位置应理解为对应前驱边，而非简单的文本先后，所以回边上的 i1 合法。

离开 SSA：并行复制与关键边#

对每个 φ，把相应输入复制放在对应前驱边上，再移除 φ。若有多个 φ，这组复制是同时发生的。a←b, b←a 不能顺序执行为 a=b; b=a，因为第二步会读到被覆盖的值；必须使用临时变量或更一般的并行复制调度算法。

关键边是源块有多个后继、目标块有多个前驱的边。复制不能直接塞到源块末尾，否则其他后继也会执行；也不能塞到目标块开头，否则其他前驱也会执行。先拆一块专门代表这条边，再把复制放进去。

实验、常见错误与验收#

先手工构造菱形图，分别从左右路径执行 φ；再构造计数循环，执行三轮。实现验证器时检查每个值唯一定义、普通使用被定义支配、φ 输入块与实际前驱相符，以及同块指令顺序。

练习：给循环增加 sum 的累加，写出两个 φ；再展示交换 a、b 所需的临时复制。

参考答案

sum0=phi [0,entry],[sum1,body]，body 中 sum1=add sum0,i0。输出 sum 时必须读取退出路径对应的最新版本。交换需要 tmp=b; b=a; a=tmp，或等价的循环分解。验收不只看结果，还要故意删掉一条 φ 前驱，确认验证器能拒绝坏 IR。
