第08章 LL、LR 与通用语法分析的地图 ​

本章目标与前置 ​

你已经写过递归下降解析器。本章把“凭代码判断走哪一支”提升为“根据集合和状态表机械决定”。重点完成两个可手算实验：为简单表达式文法计算 FIRST/FOLLOW 并建立 LL 预测表；为一个极小左递归文法建立 LR 项目集并完成移进归约。最后比较 Earley、CYK、GLR、PEG 与生成器的适用场景。

不必为了证明自己学会理论，立刻重写 Sprout 前端。手写前端的可维护性与文法理论的可推导性可以互相验证。

8.1 CFG 的四个部件 ​

上下文无关文法由非终结符集合、终结符集合、产生式集合和开始符号组成。产生式左边只有一个非终结符，右边是一串终结符与非终结符。推导反复替换非终结符，最终得到终结符串。

LL 中第一个 L 表示从左向右读输入，第二个 L 表示构造最左推导；LR 的 R 表示最右推导的逆过程。括号里的 k 表示决定下一步时使用多少个向前看符号。它们描述的是文法与分析方式，不是“一个适合简单语言，一个适合复杂语言”这样的模糊排名。

同一种语言可以有不同文法。某文法不满足 LL(1)，不代表这个语言永远无法用另一份 LL(1) 文法描述；有二义性的文法也不等于这个语言必定固有二义。讨论理论结论时先说明对象是语言还是文法。

8.2 FIRST：从这里可能先看见什么 ​

使用下面的表达式文法，n 表示整数 Token，$ 表示输入结束：

E  → T E'
E' → + T E' | ε
T  → F T'
T' → * F T' | ε
F  → ( E ) | n

FIRST(X) 是 X 可推导出的串中可能出现的第一个终结符；如果 X 能推出空串，还记录 ε。由 F 的两个分支直接得到 FIRST(F) = {(, n}。T 先读F，而F不能空，所以 FIRST(T) = {(, n}；E 同理。FIRST(E') = {+, ε}，FIRST(T') = {*, ε}。

对于串 X Y Z，先加入 FIRST(X) 中非空的元素；只有 X 可空时，才继续看 Y；若前面都可空，才继续看 Z。不能简单把所有 FIRST 集合无条件求并集，否则会引入根本不可能出现在开头的符号。

8.3 FOLLOW：这个结构后面可能是什么 ​

FOLLOW(A) 收集在某个合法句型中可能紧跟 A 的终结符。开始符号 E 的 FOLLOW 包含 $。由 F → ( E )，E 后面还可能是 )，因此：

text
FOLLOW(E)  = {), $}
FOLLOW(E') = {), $}
FOLLOW(T)  = {+, ), $}
FOLLOW(T') = {+, ), $}
FOLLOW(F)  = {*, +, ), $}
1
2
3
4
5

这些集合通过反复传播直到不再变化得到。对产生式 A → α B β，把 FIRST(β) 中除 ε 外的符号加入 FOLLOW(B)；若 β 可空，再把 FOLLOW(A) 加入 FOLLOW(B)。FOLLOW 集合不包含 ε，因为它描述真实跟随符号或结束标记，而不是“后面什么都没有”的独立 Token。

手算 n+n*n$：E 展开成 T E'；T 展开成 F T'；F 匹配 n；当前 + 让 T' 选 ε；E' 选 + T E'；第二个 T 先匹配 n，再因 * 展开 T'，匹配另一个 n；剩余可空部分消失，最后匹配 $。这正好表达乘法比加法先结合。

8.5 LR 项目：记住已经看到了哪里 ​

LR 使用项目中的圆点记录一条产生式已经识别到的位置。例如 E → E + · n 表示已经看见 E +，现在需要一个 n。项目集是分析器状态，closure 补上圆点后非终结符的候选，goto 描述识别一个符号后如何移动圆点。

8.6 手工完成一次移进归约 ​

输入 n+n$，状态栈最开始只有0，向右为栈顶：

状态栈剩余输入动作与含义
0n+n$移进n，压入状态2
0 2+n$用 E→n 归约，弹出一个符号对应状态，查goto得到1
0 1+n$移进+，压入3
0 1 3n$移进n，压入4
0 1 3 4$用 E→E+n 归约，弹出三个状态，再查goto得到1
0 1$接受

真正实现通常还维护符号值栈。移进时压入 Token 的语义值，归约时取出右部对应的孩子，创建左部 AST 节点。状态栈决定结构，值栈保存结构对应的数据；它们不能在归约长度上错位。

左递归文法在 LR 中很自然，不会像天真递归下降那样无限调用自身。这不是因为 LR 会神奇地修复错误文法，而是它先消费输入，再在合适时机把已经看见的右部归约为左部。

8.7 SLR、LALR 与 LR(1) 的差异 ​

SLR 用 LR(0) 项目加 FOLLOW 做归约决策，表相对紧凑，但 FOLLOW 汇总了不同上下文，有时会引入冲突。规范 LR(1) 项目把一个向前看 Token 与具体项目上下文绑定，决策更精确，但状态可能更多。LALR 合并具有相同 LR(0) 核的 LR(1) 状态以缩小表，合并后可能引入冲突。

移进/归约冲突意味着同一状态、同一向前看符号上，既可以移进也可以归约；归约/归约冲突意味着存在两种归约选择。优先级和结合性声明可以为某些冲突规定语言含义，但“让生成器安静下来”不等于文法已经清楚。Bison 官方手册用悬挂 else 展示这个问题。Sprout 要求分支体使用花括号，降低了这类歧义带来的阅读和实现负担。

8.8 其他算法放在什么位置 ​

方法核心思路值得注意的边界
CYK在子串区间上做动态规划常用形式要求 Chomsky 标准形；一般时间 O(n³)，空串需额外处理
Earley为每个输入位置维护带圆点项目，进行预测、扫描、完成能处理一般 CFG，最坏时间 O(n³)，某些文法类别可更快
GLR在冲突处分叉，共享分析栈与解析森林适合保留多种分析，但歧义与资源成本仍需管理
PEG/Packrat有序选择决定先尝试哪个分支，使用记忆化避免重复工作有序选择的语义不同于 CFG 的无序选择；内存、左递归支持需单独考虑
ANTLR通过生成器维护语法与目标解析器语义与性能依具体工具机制，不等于简单 LL(1) 表

想象 CYK 的表格：table[i,j] 保存区间 [i,j) 能归约成哪些非终结符；逐渐增加区间长度，枚举切分点。Earley 则把“某条规则在某个起点已经走到哪里”的项目保存在输入位置集合中。它们让你看到：解析不一定是一条确定路径，也可以是组织大量可能结构的动态规划。

第一次写 Sprout 选择递归下降，是为了让每一行源码与语法规则容易对应。将来接入更复杂现有文法、需要保留二义结构或追求生成器维护能力时，再按需求选择工具。

8.9 练习与验收 ​

练习一：对本章 LL 文法，为什么 FOLLOW(T) 包含 +，却不包含 *？

查看答案

T 后面是 E'，它可以先产生 +。* 则属于 T 内部的 T'，不会跟在已经完整结束的 T 后面。因此 * 出现在 FOLLOW(F)，而不是 FOLLOW(T)。

练习二：用 LR 表手算 n+n+n$，说明两次规则1归约如何产生左结合。

查看答案

识别前两个n后，在看到下一个+时，状态4先按 E→E+n 归约，将 n+n 变成一个E；然后再移进后一个+与n。最终树为 (n+n)+n。

本章验收：能独立重算 FIRST/FOLLOW，解释 LL 表每个非空格的来源，完整跟踪 LR 栈，并准确区分文法冲突与工具实现错误。
