22 扩展语言与结业项目：把一条主线长成完整知识地图 ​

本章目标与明确边界 ​

走完主线，你已经拥有能编译和运行 Sprout 的前端、字节码后端、VM 与 C++ 目标路径。第 13—19 章给出 IR、优化和机器后端的扩展方法。本章继续覆盖资料库中的语言设计、类型系统、DSL、AI 编译器、JIT、增量编译、自举和可信编译主题，帮助你选择下一个真正能完成的项目。

下面的语法与结构均为设计提案，当前主线不接受数组、字符串、结构体、闭包、泛型或 import。每次扩展都要同时更新规范、token/AST、静态规则、运行表示、后端和测试，不能只增加一个解析分支就宣布支持了完整特性。

数组：先决定值与引用，再决定括号 ​

数组扩展首先回答：长度是否固定、下标类型是什么、赋值复制整组元素还是共享对象、越界怎样处理。建议第一版使用固定元素类型与运行时边界检查，将数组表示为长度和连续元素区。计算地址前先证明下标非负且小于长度，再检查偏移计算不会溢出。

最小验收包括首尾元素、空数组、负下标、等于长度的下标、函数传递与共享行为。若数组按引用传递，调用可能修改调用者看到的内容，原先只分析局部整数的优化器就必须更新效果和别名模型。

二维数组还要定义布局：行优先、列优先、独立子数组或带 stride 的视图。不同表示影响地址计算与向量化；不要把宿主 vector 的行为偶然暴露为语言规范。

字符串与 Unicode ​

字符串不是“数组里装字符”一句话可以说清。UTF-8 字节长度、Unicode 码点数与用户看到的字形数量可能不同。第一版可把字符串定义为不可变 UTF-8 字节序列，提供明确的字节长度；若要按字符索引，再单独规定码点或更高级的分割规则。

词法需要转义与未闭合字符串诊断，类型系统需要相等和拼接规则，运行时需要长度与内存管理。输出中文还涉及终端编码，这是源语言值表示和宿主 I/O 之间的边界。测试至少覆盖空串、引号与反斜线、中文、多字节字符、非法转义和很长字符串。

字符串不可变可减少共享时的意外修改，但不会自动解决回收问题；多个值共享同一存储、子串视图持有大缓冲等情况都需要生命周期设计。

结构体、代数数据类型与模式匹配 ​

结构体先确定字段名、类型、布局、对齐、赋值与参数传递方式。解释器可用字段数组，本机后端则要明确偏移与 ABI。字段的源码顺序是否保证内存顺序，也应写进规范而非由实现偶然决定。

带标签联合可表达“一个值属于几个备选形态之一”。例如 OptionInt 有 None 与 Some(int)，运行时需要标签，类型检查需要匹配分支的结果一致。模式匹配增加穷尽性与不可达分支检查，可以从枚举加一个载荷的简单版本开始，不必直接复制成熟语言的全部模式语法。

这条路线连接资料库中的 type systems、programming-languages 与 pls：类型不仅用来拒绝加法错误，也用来描述数据的合法形态。语言设计先有语义，再有漂亮语法。

闭包：函数加上被捕获的环境 ​

普通函数只需代码入口，闭包还要保存它在定义位置捕获的变量。可表示为 (code_pointer, environment_pointer)。调用时把环境当作隐式参数传入。需要识别自由变量，生成环境对象，并将对捕获变量的读取改成环境字段访问。

最关键的设计问题是按值捕获还是共享可变单元。如果外层变量后来赋值，闭包应看到旧值还是新值？函数返回后闭包仍可调用，就不能引用已经销毁的栈帧。逃逸分析、堆分配与 GC 因此联系起来。

第一个实验只支持不修改的按值捕获整数；通过后再加入共享可变捕获。验收要有两个闭包各自捕获不同值、闭包逃逸外层函数、多次调用保持环境，以及递归调用时不混用环境。

泛型、类型推导与类型理论 ​

泛型的一条实现路线是单态化：按实际类型生成专门版本，运行时表示直接但可能增加代码体积；另一条是统一表示或字典传递，减少专门版本但增加运行时参数和约束处理。两者都需要定义哪些操作允许用于类型参数。

类型推导也分层次。Sprout 的 let 初始化推断只是从已知表达式结果填入类型，不等于已经实现 Hindley–Milner 推导。若研究后者，需要类型变量、约束、统一、自由类型变量和泛化，且可变引用等特性会带来额外限制。

渐进类型把部分静态类型与运行时检查结合，依赖类型允许类型表达更多关于值的性质。它们不是“静态检查越多越高级”的线性升级。建议先精确描述一个极小系统，再读 Wadler 的 Propositions as Types 或资料库 Type Systems 综述；论文中的证明规则需要配套具体演算才能理解。

模块、独立编译与包管理 ​

增加 import 前先规定模块身份、导出与私有名字、循环依赖、初始化顺序和错误位置。编译单元需要一种稳定接口表示，使调用者只凭签名就能检查，而不必每次重新解析全部实现。

缓存键至少考虑源码、依赖接口、编译选项与语言版本；漏掉一个依赖就可能复用过期结果。包管理还涉及版本约束、锁定和可重复构建，可与编译器本体分开实现。第一版只支持同一工程内显式模块，不急着接网络下载。

验收包括同名私有符号互不冲突、缺失导出清晰报错、接口改动触发依赖重建，以及纯实现改动是否能减少不必要重编译。性能优化必须建立在依赖图正确的基础上。

JIT、增量编译与交互环境 ​

AOT 在运行前生成目标；JIT 在运行过程中编译代码。JIT 仍需前端和后端，还多了代码内存管理、符号查找、重定义和安全执行边界。可以先让交互环境逐行累积源码并重新编译，再逐步优化到按函数编译，不必第一次就实现复杂 ORC 分层。

增量编译不是简单地“只重读改过的文件”。编辑一个类型定义可能影响很多使用点；修改函数实现可能只影响其本体。需要稳定实体标识、查询依赖图、失效传播和结果缓存。编辑器还要求未完成源码下继续提供部分结果，因此错误恢复与完整批量编译的策略可能不同。

调试信息、源码映射和交互打印应一起规划：JIT 代码出错时也要能回到用户输入的某一行，不能只给出一串临时内存地址。

DSL 与多阶段编译 ​

领域专用语言不一定需要全新的文本语法。嵌入式 DSL 借用宿主语言的语法和工具，独立 DSL 自己定义前端。选择取决于用户群、可控制语义、错误体验和运行目标，而不是“自己写 parser 才算语言”。

本地 Liquid 白皮书展示了借宿主生态表达智能合约领域概念的路线。它启发我们从领域需求反推抽象：哪些状态可访问、哪些操作可并行、哪些性质需检查。这里仅讨论语言工程，不把文中历史系统宣传语当成当前产品保证。

一个适合 Sprout 学习者的 DSL 结业项目是纯表达式公式语言：支持变量、函数与类型检查，编译到现有 VM。再增加规则依赖或表格计算，可直接复用数据流思想。若输出模板或配置代码，还要区分代码与数据，处理正确转义，避免生成代码注入。

AI 编译器与机器学习辅助优化 ​

编译张量程序时，高层要保留形状、数据类型、布局和算子关系，进行融合、分块与设备映射，再降到循环和更低层 IR。多面体模型适合表示某些仿射循环与依赖，但并非任意程序都能直接纳入。学习路线是先手写矩阵乘法与循环依赖，再研究调度和布局。

机器学习辅助编译器则可以预测优化启发式、生成测试程序或选择策略。Chris Cummins 的 2020 年博士论文摘要讨论了基准生成、模糊测试和启发式学习。预测性能的模型不能替代语义正确性检查：可以让模型选择已证明安全的变换，却不能因预测得分高就跳过安全前提。

实验要区分训练集与测试集，避免同一个程序的近似副本同时出现在两者中。测量编译时间、运行时间与代码大小，并记录硬件和重复测量方法；只报一个最好数字容易误导。此路线适合完成基础编译器后再选修。

并行编译、自举与形式验证 ​

并行编译可以按函数或模块分发独立工作，但共享符号表、诊断顺序与缓存需要明确同步策略。可先冻结全局签名，再并行分析函数体，最后稳定排序诊断。增添线程不应让同一份错误源码每次报不同顺序或出现数据竞争。

自举是用语言自身实现它的编译器。需要先让语言拥有足够的数据结构、字符串、文件 I/O 与内存管理能力。通常先用已有 C++ 编译器构建第 0 阶，再用它编译新语言写的编译器得到第 1 阶，再比较后续阶段。自举成功证明语言有表达能力，不自动证明编译器没有共同缺陷。

形式验证可以从很小的性质开始：表达式编译保持结果、栈高度不变量、名字重命名不改变行为、SSA 结构验证。翻译验证可逐次检查寄存器分配或优化结果，避免一开始就证明整个大型编译器。明确哪些解析、运行时和工具仍处于可信边界。

结业项目分级与验收 ​

基础项目是在干净目录复现完整主线，给出 20 个自编程序和错误用例，能解释其中一个程序每阶段表示，并通过 VM/本机差分。进阶项目从数组、字符串、模块或 SSA 中只选一个，写出完整规范、实现、正负测试和已知边界。研究项目再选 LLVM、RISC-V、张量 DSL、JIT 或翻译验证，明确比较对象与测量方法。

不要同时给语言增加五种特性然后只展示一个成功样例。一个完成得扎实的特性，应能回答“合法输入是什么、错误输入怎样拒绝、运行表示是什么、两个后端怎样保持一致、哪些优化需要调整”。把这些答案写进项目报告，才是从会跑代码走向会设计编译器。

练习：选数组或闭包，列出需要修改的六层，再写三个容易被忽略的反例。

参考答案

六层至少是规范、词法/语法、AST、语义、运行时表示、代码生成与测试；实际项目还会影响错误诊断和优化分析。数组反例可选负下标、共享修改与长度为零；闭包反例可选捕获逃逸、多个环境混淆与共享可变捕获。验收不要求实现所有高级主题，但要求选定范围内可构建、可复现、错误边界清楚，不将设计提案当作已有功能。
