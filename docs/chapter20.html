20 从零复现完整工程：里程碑与调试路径 ​

学习目标 ​

前面按知识点讲解，本章把它们重新接成一条可以独立复现的工程路线。你无需一开始就写完整语言，也不必先读完所有论文。每个里程碑只增加一种主要能力，同时保留之前已经通过的样例。理论章节解释为什么这样做，工程里程碑证明它确实做到了。

本章回到可运行主线。所有示例以 compiler/ 为工作目录；源代码是 src/sprout.cpp，规格在 SPEC.md，练习清单在 LABS.md。网站展示的片段用于讲解，完整可构建版本应以下载或仓库中的源码为准。

第一步：固定工具和最小闭环 ​

记录操作系统、编译器版本与 C++ 标准模式。先直接编译，减少生成器差异带来的干扰：

powershell
g++ -std=c++11 -Wall -Wextra -Wpedantic src/sprout.cpp -o sprout.exe
.\sprout.exe examples/hello.spr
1
2

预期两行输出为 7 和 true。类 Unix shell 改为 -o sprout 与 ./sprout。不要先复制一个大型程序验证全部功能；一个包含常量、运算和打印的小样例失败时，排查范围更小。

然后用 CMake 建立独立构建目录，避免目标文件混入源码：

text
cmake -S . -B build -DCMAKE_CXX_STANDARD=11
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
1
2
3

单配置与多配置生成器的可执行文件位置不同，按照实际构建输出寻找。MSVC 没有单独的 C++11 模式，可用其 C++14 或更新模式验证这份 C++11 基线代码。

第二步：只看词法与语法 ​

自己实现时，先写 print(1); 所需的字符识别、位置与 token；再加完整标识符和关键字；随后引入整数、运算符、注释与非法字符。用 --tokens 检查 ifx 是一个标识符，不是 if 加 x；<= 应是一个 token，而不是 < 与 =。

再建立 AST 与表达式解析。用 1+2*3 检查优先级，用 20-5-2 检查左结合，用括号检查覆盖默认优先级。完整参考程序的 --ast 会先做静态检查，因此观察用文件也要含合法的 main 与 return。若你在自己的阶段版尚未实现 Checker，可暂时提供单独的解析 dump，但不要误解参考 CLI 的行为。

第三步：先检查，再执行 ​

写函数签名表，再分析函数体，使前向调用和互递归有明确依据。为每个变量分配绑定与槽位。先拒绝未声明名字、同块重声明、类型不符、参数不符与缺少返回，再允许进入后端。

推荐每添加一条合法样例，同时添加一个只改一个点的错误样例：把 1+2 改成 true+2；把已声明 x 改成 y；把函数两个参数改成一个。这样能确认“错误在哪里被拒绝”，而不是让所有问题都在 VM 中偶然暴露。

静态检查无法证明所有运行行为安全，所以除零和溢出仍要由运行时处理。区分这两层职责，有助于理解为什么“程序类型正确”不等于“程序一定正常结束”。

第四步：逐项扩展字节码 ​

先支持常量、算术、print、return；再加局部变量 LOAD/STORE；然后加 if 回填和 while 回边；最后引入 CALL/RET 和帧。短路逻辑独立检查，不要暂时用普通布尔二元运算顶替后就忘记修正。

每项都先写指令清单，再用 --bytecode 对照。函数调用先测 sub(a,b)，因为减法能暴露参数反序；之后测连续调用，再测嵌套，最后递归。只测试一个 Fibonacci 无法清楚定位调用约定错误。

第五步：端到端结业样例 ​

把下面保存为 capstone.spr：

sprout
fn fib(n: int) -> int {
    if (n < 2) { return n; }
    return fib(n - 1) + fib(n - 2);
}
fn sum_to(n: int) -> int {
    let i = 1;
    let total = 0;
    while (i <= n) {
        total = total + i;
        i = i + 1;
    }
    return total;
}
fn main() -> int {
    print(fib(10));
    print(sum_to(10));
    print(false && (1 / 0 == 0));
    return 0;
}

随后生成 C++ 并编译成本机程序，比较三行输出。先确认生成命令成功再编译，避免错误信息被重定向成一个看似存在的目标文件。PowerShell 的编码细节见第 17 章和 compiler/README.md。

按首次分歧定位错误 ​

若结果错误，按流水线找到最早错误表示。token 已错就不调 parser；AST 错就不改 VM；AST 与绑定正确而字节码错，就看生成器；字节码正确而执行错，就单步检查 VM 状态。本机路径独有错误则重点看 CppEmitter 的求值顺序、名字映射和运行时。

可以临时加入每步日志：函数、ip、指令、操作数栈、局部槽位。调试日志写标准错误，程序打印留标准输出，避免日志破坏差分比较。确认问题后将最小复现加入回归用例，再移除或关闭大量日志。

工程组织与可维护性 ​

单文件版本降低复制与跳转成本，适合初学者阅读。理解阶段边界后，可以拆出 lexer、parser、sema、bytecode、vm、cpp-emitter 与 driver。拆分应保持输入输出契约，不要把 Parser 直接依赖 VM 内部结构。

一次提交只完成一类能力；保存语言规格与测试，避免代码已经支持新语法而文档仍在讲旧规则。错误诊断也是功能的一部分：行列、类别与明确消息应随阶段演进，不能最后才补。

练习与验收 ​

自己从空文件实现到只支持算术打印，再加变量。记录每个里程碑的一个正例和一个反例。找一个故意把减法参数顺序反转的实现，说明它第一次在哪层偏离。

参考答案

若 AST 左右子树正确，但 dump 的 LOAD/压参顺序反了，首次分歧在生成器；若 dump 正确，VM 弹栈颠倒，则在执行器。结业验收应能在干净目录构建、运行 capstone、拒绝静态错误、受控处理运行时错误，并用 C++ 目标重复得到一致输出。只演示网站或只附一张运行截图都不足以替代可复现命令。
