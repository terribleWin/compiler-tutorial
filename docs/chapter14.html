14 数据流分析：让信息沿控制流传播 ​

学习目标与前置知识 ​

本章是三地址 IR 的扩展实验。先完成第 13 章，能准确列出每块的前驱、后继。你将学会活跃变量的含义、IN/OUT 方程、迭代与工作队列，并理解保守分析为什么宁可多保留一个值，也不能漏掉真正需要的值。

一个值什么时候活着 ​

假设执行 x=10 后，在任何可能路径上都不会在下一次覆盖 x 之前读旧 x，那么这个值不必继续占寄存器。只要存在一条路径会在覆盖之前读取它，它在当前位置就活跃。活跃的是程序点上的已有值，不是“整个程序出现过这个名字”。

这是反向问题：后面要读什么，决定前面要留什么。常量传播通常是正向问题：前面已经确定的信息影响后面。分析方向必须由问题本身决定，不能所有问题都套上“从入口走一遍”。

从块内部提取 USE 和 DEF ​

从上到下扫描块。DEF 包含块中定义的变量；USE 包含在本块首次定义之前读取的变量。对于 x=x+1，右侧先读旧 x，因此 x 同时属于 USE 与 DEF。对于 x=1; y=x+2，x 不属于 USE，因为入口无需提供旧 x。

块内容USEDEF
x=1; y=x+2{}
x=x+1
print(y){}

这里先分析无指针、无别名的标量。增加数组、引用或可修改全局量的函数后，内存读写必须有额外建模，不能只比较变量名字。

把直觉写成方程 ​

IN[B] 表示进入 B 时需要的旧值；OUT[B] 表示离开 B 时仍需保留的值。任意后继需要某值，B 离开时就要保留它，因此合并使用并集。

text
OUT[B] = 所有后继 S 的 IN[S] 的并集
IN[B]  = USE[B] ∪ (OUT[B] - DEF[B])
1
2

第二式分两部分：本块开始就读取的值必须从入口提供；后继需要而本块没有重新定义的值也必须从入口带过来。若 B 覆盖了 x，后继需要的新 x 不能反过来要求入口旧 x 活跃。

图的边为 B0→B1、B1→B1、B1→B2：

text
B0: x=1; y=2; jump B1
B1: x=x+y; branch x<10, B1, B2
B2: print(x); return 0

USE/DEF 分别为 B0:{} / {x,y}，B1:{x,y} / {x}，B2:{x} / {}。先把所有 IN/OUT 设为空，再按 B2、B1、B0 逆序更新。

第一轮：B2 得 IN={x}；B1 根据后继当前结果得 OUT={x}、IN={x,y}；B0 得 OUT={x,y}、IN={}。第二轮：B1 自环把 y 传回，OUT 增加为 {x,y}，IN 不变；其他不变。第三轮完全不变，达到不动点。

块最终 IN最终 OUT解释
B0{}两值都由 B0 提供
B1y 还会在下一轮使用
B2{}打印后函数结束

只做一遍会漏掉回边带来的需求。不同更新顺序影响迭代轮数，但在这个分析中不影响最终最小不动点。表格中的每个集合都能用方程重新验证，不需要相信某段程序的输出。

从全量扫描到工作队列 ​

第一版反复扫描所有块直到集合稳定，最容易写对。之后改为工作队列：某块 IN 改变，通知它的前驱，因为前驱的 OUT 可能变化。方向是向前驱传播，不是后继。

text
所有块入队
当队列非空：
    取 B
    newOut = union(IN[S])，S 为 B 后继
    newIn  = USE[B] union (newOut minus DEF[B])
    保存 OUT[B] = newOut
    若 newIn != IN[B]：
        保存 IN[B] = newIn
        将 B 的前驱入队

即使 IN 没变也要保存新的 OUT，因为指令级扫描还要用它。用 inQueue 标记避免重复入队。集合最初使用 set 即可，正确后再换位向量，不要让容器优化先于算法正确性。

为什么终止，为什么保守 ​

函数只有 N 个变量，集合最多有 N 个元素。从空集出发，传递函数单调，信息只增加，所以不会无穷增长。更正式地说，它在有限幂集格上迭代到不动点。第一次接触这些术语时，先观察上例中的集合每轮怎样变化，再回头理解抽象定义。

合并使用并集意味着：即使只有一条可能路径读取 x，也保留 x。这条路径可能实际不可达，但在没有证明之前必须考虑。多保留影响效率，漏保留可能改变结果。正确性与精度是不同指标：分析可保守而正确，也可看起来精确却遗漏真实路径。

指令级活跃与属性文法的连接 ​

从 OUT[B] 开始反向扫指令。对 t=add a,b，先从集合删去 t，再加入 a、b。例如指令后的集合为 {t,c}，之前就是 {a,b,c}。由此可生成活跃区间、干涉图，为第 17 章分配寄存器。

数据流方程也能视为属性关系：一个块的 IN/OUT 是由邻居属性计算的值。普通 AST 属性常能沿树一次求出，而 CFG 有环，需要求解循环方程。循环属性文法研究的正是如何描述、调度这样的依赖。这个联系能把资料库中的 attributed-grammars 与优化章节接起来，但不能因此认为所有循环属性都必然快速可求；终止性仍需具体论证。

常见错误、练习与验收 ​

常见错误包括将所有出现过的变量都塞进 USE、把减去 DEF 写成并入 DEF、只跑一轮、IN 改变时通知后继、以及修改 CFG 后继续使用旧结果。

练习一：B2 增加 print(y)，重新求解。练习二：B1 改成 x=5; branch x<10,B1,B2，旧 x 是否还在 IN[B1]？练习三：说明块内扫描为什么必须先 kill 定义再 gen 使用。

参考答案与验收

第一题 B2 的 IN 变为 {x,y}，其余最终结果在本例不变。第二题旧 x 不再需要进入 B1，因为比较使用块内新 x；y 若也不再读取，就不应保留。第三题 x=x+1 必须保留入口旧 x，先删再加才能得到正确结果。验收要覆盖直线、菱形、自环和多出口，并验证坏 CFG 先被结构检查器拒绝。
